# 0076. Project Browser 카드와 최근 프로젝트

- 상태: 채택·구현
- 관련: [0002](0002-project-launcher-and-assets.md), [0003](0003-native-folder-dialog.md), [0027](0027-windows-editor-packaging.md)
- ADR 0002의 시작 화면 배치와 최근 프로젝트 미지원 범위를 대체한다.

## 배경과 제약

기존 시작 화면은 생성·열기 모드를 전환하는 작은 폼이다. 사용자는 Unreal Project Browser처럼 프로젝트를 카드로 선택하고 하단에서 경로·이름을 확인하는 구성을 원한다. 왼쪽 분류는 제공하지 않고 기존 에디터 Theme·Ui 및 한글 입력 계약을 유지한다. 프로젝트 생성·검증·시작 인자는 기존 로직을 재사용한다.

## 대안과 판단 기준

기존 폼을 확장하면 최근 프로젝트를 비교하기 어렵다. 프로젝트 폴더 전체를 자동 검색하면 탐색 범위와 비용을 새로 정해야 한다. 사용자가 성공적으로 연 프로젝트만 사용자 설정에 기록하면 별도 탐색 없이 다음 실행에서 선택할 수 있다.

## 결정과 근거

화면 제목과 창 제목에 Project Browser를 사용한다. 왼쪽 분류 없이 New Project 카드와 최근 프로젝트 카드를 배치하고, 하단에 Project Location·Project Name 및 Browse·Open·Cancel을 둔다. 생성 카드에서는 이름을 편집하며 Open 대신 Create를 제공한다. 기존 프로젝트 이름은 매니페스트에서 읽어 표시한다. 카드는 공통 대체 그림을 사용하며 실제 게임 장면 캡처나 프로젝트 파일 형식 변경을 요구하지 않는다.

최근 프로젝트는 LÖVE 사용자 저장 위치의 recent-projects.json에 version·projects(path, name)로 저장한다. 성공적으로 연 순서대로 최대 30개를 보관하며 Windows 경로 대소문자와 구분자를 정규화해 중복을 제거한다. 저장 실패는 성공한 열기를 취소하지 않는다. 오래된 경로도 목록에는 유지하되 열 때 기존 Project 검증을 수행해 오류를 화면에 표시한다.

생성 모드에는 Open Existing 버튼을 제공해 최근 목록 유무와 관계없이 열기 모드로 돌아갈 수 있게 한다. Browse는 모드별 폴더 선택 의미를 유지하며, 이름 표시에는 매니페스트의 읽기 전용 조회만 사용한다. Project.open은 누락 폴더 생성·Sources 이동·에셋 목록 갱신을 수행하므로 Open 제출 또는 최근 카드 더블클릭에서만 호출한다. 폴더 선택 후 Cancel은 프로젝트 파일을 변경하지 않는다.

ProjectStart는 화면·입력을 담당하고 RecentProjects에 목록의 정규화·저장을 위임한다. Project 생성·열기와 네이티브 FolderDialog 계약은 유지한다. 코드 이름 ProjectStart는 시작 진입 책임을 나타내므로 표시 이름만 바꾼다.

## 예상 결과

- 긍정: 프로젝트 선택과 생성 진입을 카드에서 구분하고 경로·이름을 한곳에서 확인한다.
- 부정: 최근 목록에 이동·삭제된 경로가 남을 수 있으며 해당 경로는 Browse로 다시 지정해야 한다.
- 중립: 기존 프로젝트 매니페스트·실행 인자와 에디터 테마를 유지한다. 프로젝트 내용의 썸네일 생성은 추가하지 않는다.
