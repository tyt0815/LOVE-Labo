# 0101. 새 프로젝트에 경로 기반 Git 제외 규칙을 제공한다

- 상태: 채택·구현
- 날짜: 2026-10-19
- 관련: [0048](0048-user-guides-and-project-agent-instructions.md), [0088](0088-project-lua-build-and-game-cli.md), [0100](0100-conditional-property-editing.md)

## 배경과 제약

새 프로젝트를 Git으로 관리할 때 배포 출력과 에디터 캐시가 저장소에 포함되지 않아야 한다. 에셋 ID와 프로젝트 설정은 복원에 필요하므로 추적할 수 있어야 하며, 기존 사용자 규칙을 보존해야 한다.

## 대안과 판단 기준

- 실행 파일·이미지·압축 파일 확장자를 일괄 제외하면 사용자가 관리하는 에셋도 누락될 수 있다.
- 프로젝트를 열 때마다 제외 규칙을 보정하면 기존 사용자 파일을 변경하게 된다.
- 새 프로젝트 생성 시 알려진 생성 경로만 제외하면 소스 추적을 유지하면서 사용자가 출력 경로에 맞춰 규칙을 확장할 수 있다.

## 결정 및 근거

Project.create의 기존 파일 생성·실패 정리 경로에서 `.gitignore`를 생성한다. 루트 Build/·build/, .labo/, 임시 asset-index.json·asset-move.json과 운영체제 생성 파일을 제외한다. Assets, assets.json, project.labo, plugins.json, conf.lua, Tools와 안내 문서는 제외하지 않는다. Git 초기화는 수행하지 않으며 기존 프로젝트를 열 때 파일을 추가하거나 덮어쓰지 않는다.

생성 AGENTS.md와 로컬 안내에는 ADR 0100의 enabledIf 활용을 권장하고 Inspector 편집 제한과 런타임 동작 조건의 차이를 명시한다.

## 예상 결과

- 긍정: 기본 빌드 출력과 로컬 캐시가 Git 추적 후보에서 빠지고 프로젝트 원본과 에셋 ID는 보존된다.
- 부정: 다른 출력 경로를 사용하는 프로젝트는 사용자가 제외 규칙을 추가해야 한다.
- 중립: 기존 프로젝트의 규칙과 AI 안내는 그대로 유지되며 엔진·저장 형식 버전은 변경하지 않는다. 현재 0.1.0-dev 배포 준비 범위에 포함한다.
