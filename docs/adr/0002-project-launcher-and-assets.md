# 0002. 프로젝트 런처와 Assets 탐색 경계

- 상태: 채택
- 폴더 선택 UI 결정은 [ADR 0003](0003-native-folder-dialog.md)으로 대체
- 날짜: 2026-10-08

## 배경과 제약

에디터 시작 시 프로젝트 생성 또는 열기를 제공하고, 열린 프로젝트의 `Assets`만 하단 브라우저에 표시한다. 외부 프로젝트는 호스트 설치 경로와 LÖVE save directory 밖에 존재할 수 있다. 이번 범위는 프로젝트와 폴더 탐색이며 현재 레벨 선택·자동 로딩, 에셋 임포트, 에셋 인스펙터는 포함하지 않는다. 기존 Edit/Runtime 분리와 중앙 월드 원점 결정(ADR 0001)을 유지한다.

## 대안과 판단 기준

- 임의 폴더를 프로젝트로 취급하면 간단하지만 일반 폴더와 프로젝트를 구별하거나 형식 버전을 검증할 수 없다.
- 프로젝트 정보 파일을 사용하면 최소한의 이름·형식 검증과 향후 명시적인 버전 변경이 가능하다.
- LÖVE 가상 파일시스템만 사용하면 임의 외부 폴더 생성 및 쓰기를 처리할 수 없다. 셸 명령을 만들면 인용·Unicode·입력 검증 부담이 커진다.
- 좌측 에셋, 우측 위 계층·아래 인스펙터 배치는 계층과 인스펙터가 세로 공간을 나눠 쓴다. 기존 좌·우 패널을 유지하고 하단에 에셋 영역을 추가하면 두 패널의 탐색 흐름을 유지할 수 있다.

## 결정 및 근거

1. 새 프로젝트는 기존 부모 폴더 아래에 새 디렉터리로 생성한다. 루트에는 UTF-8 JSON 형식 `project.labo`(`version: 1`, `name`)와 `Assets/`를 만든다. 기존 디렉터리·파일은 덮어쓰지 않는다. 생성 실패 시 이번 생성에서 만든 파일·빈 폴더만 정리한다.
2. 프로젝트 열기는 정보 파일의 형식·이름과 접근 가능한 일반 `Assets` 디렉터리를 검증한 뒤 에디터를 생성한다. 실패는 런처에 표시한다. 런처에서 경로 입력, 붙여넣기, 내장 폴더 선택을 지원한다.
3. 외부 파일시스템 접근은 Editor의 `host_filesystem`에 둔다. 현재 Windows/LuaJIT에서 Unicode Win32 API를 사용한다. 다른 OS와 exported runtime의 파일 접근은 이 호스트 모듈을 공유한다고 가정하지 않는다.
4. 브라우저는 `Assets` 또는 그 하위 canonical project-relative 경로만 탐색한다. 폴더 연결점·심볼릭 링크는 표시하되 내부로 들어가지 않는다. 폴더 트리는 펼친 부분만 읽고 파일 목록은 현재 폴더만 읽는다. 외부 변경은 명시적인 Refresh로 반영한다.
5. 하단 에셋 영역은 계층과 중앙 뷰포트 아래를 함께 사용한다. 우측 인스펙터는 전체 높이를 유지한다. 하단 높이는 조절·접기가 가능하다. 에셋 클릭과 키 입력은 LObject 선택·편집에 전달하지 않는다.
6. 프로젝트를 열어도 레벨 파일은 자동으로 선택하거나 실행하지 않는다. 기존 에디터는 빈 메모리 Level로 시작한다. 현재 레벨 연결 및 계층/뷰포트 기능 확장은 별도 작업에서 결정한다.

## 예상 결과

- 긍정: 생성→열기→외부 Assets 탐색 흐름이 생기며, 프로젝트 파일과 에셋을 설치 폴더에서 분리한다. 한글 이름·경로를 지원하고 잘못된 열기가 현재 상태를 바꾸지 않는다.
- 부정: 외부 프로젝트 호스트 접근은 현재 Windows만 지원한다. 변경 자동 감지, 썸네일·미리보기, 최근 프로젝트, 실행 중 프로젝트 전환은 제공하지 않는다.
- 중립: Asset 선택은 인스펙터에 연결하지 않는다. 저장된 Transform과 좌표 방향, Edit/Runtime 상태는 변경하지 않는다. 기존 레벨 문서 API를 유지한다.
