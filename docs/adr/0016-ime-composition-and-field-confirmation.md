# 0016. IME 조합 표시와 입력칸 확정

- 상태: 채택
- 후속 부분 대체: [ADR 0023](0023-text-edit-and-component-group-layout.md)의 커서·범위 선택·중간 입력
- 날짜: 2026-10-09
- 확장: [ADR 0006](0006-widget-canvas-and-asset-views.md)의 포커스 입력 전달

## 배경과 제약

한글 입력이 한 글자 늦게 표시되고, 스페이스·방향키 없이 확인하거나 다른 입력칸으로 이동하면 마지막 글자가 사라진다. 기존 구현은 `love.textinput`의 확정 문자열만 처리하고 `love.textedited`의 조합 문자열을 무시했다. LÖVE 11.5의 입력 이벤트를 사용하며 조합 상태는 프로젝트 데이터와 분리된 에디터 임시 상태여야 한다.

## 대안과 판단 기준

- 확정 이벤트만 기다리면 OS의 조합 종료 전에 처리되는 클릭·Enter에서 마지막 글자를 잃는다.
- 조합 이벤트마다 저장 문자열에 덧붙이면 자모 갱신 및 확정 이벤트에서 글자가 중복된다.
- 공통 조합 처리 모듈과 입력칸별 임시 상태를 사용하면 기존 입력칸의 문자열·전체 선택 방식을 유지하면서 조합 표시와 종료 규칙을 공유할 수 있다.

## 결정 및 근거

1. `love.textedited`를 시작 화면 또는 EditorApp → UIRoot → 팝업/포커스 위젯으로 전달한다. 인스펙터 어댑터는 기존 인스펙터와 클래스 인스펙터에 전달한다.
2. `editor/ui/ime.lua`가 조합 표시·확정·취소를 제공한다. 입력칸은 확정 문자열과 조합 문자열을 따로 보유한다. 조합 이벤트는 이전 조합을 교체하며, 확정 입력은 조합을 비우고 확정 문자열에 한 번 추가한다. 공통 입력칸은 조합 문자열을 밑줄로 표시한다.
3. Enter·확인 클릭·다른 입력칸으로 이동·프로퍼티 편집 종료에서는 남아 있는 조합을 포함한다. Escape·대화상자 취소는 조합을 버린다. 조합 중 백스페이스와 일반 키는 기존 확정 문자열을 수정하지 않고 IME에 맡긴다. 방향키·필드 이동·클립보드 명령은 조합을 종료한 뒤 처리한다.
4. 수동 종료 시 LÖVE 텍스트 입력을 재시작해 OS 조합을 초기화한다. 동일 이벤트 처리 묶음에서 뒤늦게 오는 같은 확정 문자열은 무시하고, `love.update`에서 무시 목록을 비운다. 다음 프레임의 동일 문자 입력은 정상 처리한다.

## 예상 결과

- 긍정: 조합 글자가 즉시 보이고, 별도의 스페이스 없이 마지막 글자까지 적용된다. 자모 삭제가 이전 확정 글자를 지우지 않으며 다음 입력칸으로 조합이 넘어가지 않는다.
- 부정: OS 조합 종료와 이벤트 순서가 플랫폼마다 다르므로 실제 IME에서의 확인이 필요하다. 수동 확정은 현재 표시된 조합 문자열을 사용한다.
- 중립: 파일 형식·Core·기존 문자열 끝에서 입력하는 방식은 유지한다. 커서 이동과 범위 선택을 갖춘 전체 텍스트 편집기를 도입하지 않는다.
