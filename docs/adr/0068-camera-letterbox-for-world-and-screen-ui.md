# 0068. 카메라 비율의 실제 게임 영역과 레터박스

- 상태: 승인·구현
- 부분 대체: [ADR 0046](0046-camera-screen-canvas-and-component-order.md)의 Canvas 전체 창 영역 계약

## 배경과 제약

PIE와 독립 실행 창의 비율이 카메라 기준 비율과 다를 수 있다. 게임 화면은 카메라의 viewWidth:viewHeight 비율을 유지하고 남는 영역은 검은 여백으로 보여야 한다. 렌더링과 입력, CLI 검증은 같은 좌표 계약을 사용해야 한다.

## 대안과 판단 기준

월드만 잘라내고 Canvas를 창 전체에 그리면 UI가 레터박스를 덮고 보이지 않는 영역에 입력 대상이 생긴다. 해상도에 맞춰 카메라 범위를 확장하면 플랫폼마다 보이는 내용이 달라진다. 월드와 Canvas 모두 실제 게임 영역으로 제한하는 방식을 선택한다.

## 결정 및 근거

Viewport는 주어진 공간 중앙에 카메라 비율을 유지한 최대 사각형을 배치한다. x/y/width/height는 이 실제 게임 영역이다. 카메라 zoom은 보이는 월드 크기를 바꾸지만 화면 비율은 바꾸지 않는다. 카메라가 없으면 주어진 영역을 그대로 사용한다.

PIE는 뷰포트 패널의 공통 외곽 간격을 제외한 내부 전체를 사용한다. 실행 중에는 Scene View/Game View 제목이나 제목용 여백을 두지 않는다. 렌더링과 포인터 입력 모두 같은 전체 영역에서 레터박스를 계산한다.

Canvas의 matchViewport는 레터박스를 제외한 실제 게임 영역을 사용하며 1단위는 화면 1픽셀로 유지한다. 모든 draw는 해당 영역으로 클리핑한다. 여백에서 새 클릭은 발생하지 않지만 기존 캡처의 move/up은 전달하고 inside=false로 표시한다. GameView·독립 Host·CLI 입력은 같은 Viewport를 사용한다.

## 결과

- 긍정: 실행 환경 간 비율 유지, UI·입력·렌더링 영역 일치.
- 부정: Canvas가 창 전체를 사용하던 레벨은 좁아진 게임 영역에 맞춰 배치를 조정할 수 있다.
- 중립: 자동 앵커·기준 해상도 UI 확대는 제공하지 않는다. 카메라 없는 게임의 기본 좌표계는 유지한다.
