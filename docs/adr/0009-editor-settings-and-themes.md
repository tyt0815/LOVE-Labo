# 0009. 에디터 공통 설정과 JSON 테마

- 상태: 채택
- 날짜: 2026-10-08
- 확장: [ADR 0006](0006-widget-canvas-and-asset-views.md)의 UI 표현과 [ADR 0008](0008-context-menu-and-project-entries.md)의 팝업

## 배경과 제약

기존 계층·인스펙터와 새 브라우저·팝업의 색상이 각각 하드코딩되어 색감이 일치하지 않는다. 사용자가 JSON으로 색 조합을 편집하고 에디터 설정에서 테마를 선택하기를 요청했다. 설정은 게임 프로젝트에 포함하지 않고 에디터에 둔다. Core나 프로젝트 데이터에 UI 의존성을 추가하지 않는다.

## 대안과 판단 기준

- 프로젝트별 설정은 프로젝트 이동·공유에 따라 에디터 외형까지 바뀌므로 요청한 에디터 공통 설정과 맞지 않는다.
- 소수의 공통 팔레트만 조합하면 버튼·아이콘·뷰포트 등 서로 다른 용도의 색을 독립적으로 조절하기 어렵다. 글자·경계·선택 등 공통 색을 공유하면서 필요한 용도별 색을 제공한다. 새 항목이 없는 기존 테마는 코드의 기본값을 상속하므로 UI 확장이 즉시 모든 사용자 테마의 수정을 요구하지 않는다.
- 기본 JSON과 내장 대체값을 함께 두면 기본 테마의 원본이 중복된다. 사용자 요청에 따라 기본 테마는 코드 안에만 두고 JSON은 추가 테마에만 사용한다.

## 결정 및 근거

1. 에디터 설치/소스의 `editor/settings.json`에 `version: 1`과 `theme` 이름을 저장한다. 시작 시 한 번 읽으며 변경 후 재시작하여 적용한다. GUI 설정 화면과 실시간 파일 감시는 이번 범위에 포함하지 않는다.
2. 테마는 `editor/themes/<이름>.json`에 `version: 1`과 `colors`를 둔다. 이름은 영문·숫자·밑줄·하이픈만 허용하여 다른 경로를 읽지 않는다. 색은 `#RRGGBB` 또는 `#RRGGBBAA` 문자열이다. 사용자 테마에서 생략한 역할은 기본 테마를 상속한다.
3. `editor/theme.lua`가 기본 테마의 유일한 원본과 설정·테마 검증을 담당한다. `default` 선택은 외부 테마 파일을 읽지 않는다. 설정 없음·선택 없음·선택 파일 없음·잘못된 JSON/색상은 코드에 내장된 기본 테마로 돌아간다. 알 수 없는 색상 역할도 오타로 보고 해당 테마 전체를 거부한다.
4. 기본 `default`는 기존의 어두운 색감과 파란 선택 강조를 유지한다. 계층·인스펙터·브라우저는 panel·border·selection·text 색을 공유한다. 버튼·입력칸·파일 아이콘·폴더 아이콘·격자·축 등은 독립 조절 가능한 용도별 항목을 둔다. 새 UI에서 별도 색이 필요하면 기본 테마와 제공하는 JSON에 함께 추가하며, 기존 사용자 JSON에서 생략된 새 항목은 내장 기본값을 사용한다. 경로 호버 애니메이션은 테마 색을 보간한다.
5. `atom-one-light`는 [VS Code Atom One Light 팔레트](https://github.com/akamud/vscode-theme-onelight/blob/master/themes/OneLight.json)를 참고하여 밝은 회색 배경, 짙은 글자, 파란 강조와 빨강·초록 보조색을 에디터 역할에 맞춰 구성한다. 외부 테마의 설정 전체를 그대로 이식하는 계약은 아니다.
6. 에디터의 격자·축·원점·임시 LObject 디버그 표시도 역할 색을 사용한다. 실제 이미지 썸네일은 원래 색을 보존한다. 테마는 Core나 프로젝트 Runtime의 실제 렌더링 색을 제어하지 않는다.

## 예상 결과

- 긍정: JSON에서 색을 변경하거나 테마 이름을 선택할 수 있고 이전·새 UI의 색 역할이 일관된다. 잘못된 설정이 에디터 시작을 막지 않는다.
- 부정: 색 역할의 이름을 외부 설정 계약으로 유지해야 하며, 용도별 색이 추가될 때 제공하는 테마 JSON도 관리해야 한다.
- 중립: 프로젝트 파일 형식·레이아웃 크기·입력 동작은 바뀌지 않는다. 개인 설정 저장 위치 분리와 설정 GUI는 이후 필요에 따라 결정한다.
