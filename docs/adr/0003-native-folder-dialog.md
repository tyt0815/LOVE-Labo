# 0003. 프로젝트 시작 화면에서 Windows 기본 폴더 선택 사용

- 상태: 채택
- 날짜: 2026-10-08
- 부분 대체: [ADR 0002](0002-project-launcher-and-assets.md)의 내장 폴더 선택 UI

## 배경과 제약

사용자가 프로젝트 시작 화면의 Browse를 Windows 기본 방식으로 변경하도록 요청했다. 생성 시 부모 폴더, 열기 시 프로젝트 폴더를 고르는 기존 의미와 한글 경로 지원을 유지해야 한다. 외부 프로젝트 접근은 현재 Windows/LuaJIT을 대상으로 한다.

## 대안과 판단 기준

- 자체 폴더 선택기는 별도 종속성이 없지만 Windows의 즐겨찾기, 드라이브 탐색, 익숙한 경로 입력 경험을 반복 구현해야 한다.
- PowerShell 등 별도 프로세스로 선택기를 실행하면 셸 실행·출력 인코딩·부모 창 관리가 추가된다.
- Windows Common Item Dialog를 직접 호출하면 추가 실행 파일 없이 운영체제의 폴더 선택 경험을 제공한다. COM 객체와 할당 메모리의 수명 관리를 명시적으로 처리해야 한다.

## 결정 및 근거

`editor/folder_dialog.lua`에서 LuaJIT FFI를 통해 `IFileOpenDialog`를 폴더 선택 모드로 호출한다. 현재 활성 LÖVE 창을 부모로 지정하며, 입력된 경로가 유효하면 해당 폴더에서 시작한다. 잘못된 초기 경로는 Windows 기본 위치를 사용한다. 선택 결과는 UTF-8 경로로 반영한다. 취소는 오류가 아니며 기존 경로를 유지한다. API 실패는 시작 화면에 표시한다.

기존 내장 선택기와 그 상태·이벤트 처리는 제거한다. 경로 직접 입력과 붙여넣기는 유지한다. Windows 문자 변환은 파일시스템과 대화상자가 공유한다. COM 초기화 호출 횟수, 인터페이스 참조, 경로 메모리는 성공·취소·실패 경로 모두에서 정리한다.

사용자 문서와 소스에서는 이 화면을 ‘프로젝트 시작 화면’으로 통일한다. 사용자의 명칭 통일 요청에 따라 모듈은 `editor/project_start.lua`, 객체는 `ProjectStart`를 사용한다.

## 예상 결과

- 긍정: 익숙한 Windows 폴더 탐색과 한글 경로 선택을 사용하고 에디터 내 폴더 선택 코드를 줄인다.
- 부정: 대화상자가 열린 동안 LÖVE의 일반 프레임 처리는 대기한다. 다른 OS의 기본 선택기는 별도 구현이 필요하다.
- 중립: 프로젝트 형식, 생성·열기 검증, Assets 브라우저와 현재 레벨의 책임은 변경하지 않는다.
