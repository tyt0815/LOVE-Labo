# 0067. 고정 실행·일시정지·정지 버튼과 상태 테두리

- 상태: 승인·구현

## 배경과 제약

실행 버튼을 일시정지 버튼으로 바꾸면 같은 위치의 의미가 바뀐다. 사용자는 세 버튼을 고정하고 가능한 동작과 외곽선으로 상태를 보여주기를 원한다. 일시정지에서 World를 다시 생성하거나 실행 값을 편집 데이터로 역전파하면 안 된다.

## 대안과 판단 기준

토글 버튼은 공간을 줄이지만 동작이 덜 명확하다. 세 버튼을 고정하고 비활성 상태를 표시한다. 런타임 저장·복원 대신 같은 World의 진행만 멈춘다.

## 결정과 근거

상단에 Play·Pause·Stop을 고정한다. 편집은 Play만, 실행은 Pause·Stop, 일시정지는 Play(재개)·Stop만 활성화한다. Run 메뉴도 같은 상태·함수를 사용한다. Pause는 Update·포인터 입력·디버그 수명을 멈추고 렌더링·에디터 UI를 유지한다. 포인터 캡처는 해제한다. Play는 같은 World를 재개하고 Stop은 기존 편집 데이터로 돌아간다.

Viewport Toolbar는 씬뷰와 같은 폭으로 뷰포트 위에 배치한다. 제목 없이 기존 Ui.panel의 라운드 외곽선·6px 패딩을 사용한다. 상단은 계층·Inspector 패널과 같으며 뷰포트는 툴바 아래에서 시작한다. 실행 버튼은 중앙, 스냅은 오른쪽에 배치하며 겹치는 폭에서는 다음 줄로 내린다. 실행 중에도 스냅을 표시하지만 비활성 상태로 입력을 받지 않는다. 실행 행 높이는 Ui.METRICS.playBarHeight로 조절하고 전체 높이는 스냅 배치에 따라 계산한다.

실행 테두리는 초록, 일시정지는 주황이며 Theme의 playRunning·playPaused로 변경한다. 편집은 기존 테두리를 사용한다.

게임 API 검수 예제는 테스트 프로젝트의 일반 Assets/Examples에 둔다. 제품 제공 기능을 플러그인에 두는 원칙을 프로젝트 전용 예제 코드까지 확대하지 않으며 예제 플러그인·공개 별칭을 따로 만들지 않는다.

```text
PlayControls·Run 메뉴 ──의존──> EditorApp의 실행 상태·함수
ViewportToolbar ──포함──> PlayControls·ViewportControls
EditorApp ──소유──> Runtime World (Pause 동안 유지)
```

## 결과

- 긍정: 고정된 위치와 명확한 상태, 같은 시뮬레이션 재개.
- 부정: 상단 공간을 사용한다. 사용자가 draw 안에서 직접 변경하는 상태까지 정지시키지는 않는다.
- 중립: 배포 World API·레벨 형식·편집/런타임 분리는 유지한다.
