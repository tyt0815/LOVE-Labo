# 0056. Prefab 생성과 기존 계층 연결

- 상태: 승인·구현
- 관련: [0055](0055-prefab-container-and-sourced-object-roots.md)의 컨테이너와 원본 구성 구분.

## 배경과 제약

Create Prefab은 에셋만 저장하고 선택 계층을 그대로 두어 사용자가 새 원본으로 다시 배치해야 했다. 사용자는 생성과 동시에 기존 계층을 새 Prefab으로 연결하기를 요청했다. 기존 ID·이름·Transform과 외부 참조를 보존하며 상속 구성 내부를 교체하지 않아야 한다.

## 대안과 판단 기준

기존 계층을 삭제하고 새 인스턴스를 생성하는 대안과 기존 객체의 원본·생성 경로만 갱신하는 대안을 비교했다. ID를 사용하는 object/script 참조와 Main Camera, 배치 위치 보존을 기준으로 후자를 선택했다. 상속 자손 하나를 임의 교체하면 기존 원본에서 다시 생성되므로 해당 경우는 배치 루트를 선택하도록 안내한다.

## 결정과 근거

캡처가 authoringId별 새 Prefab 내부 경로를 반환한다. 생성 성공 후 기존 계층의 원본과 prefabRootId/prefabNodePath를 갱신한다. ID·이름·Transform·외부 부모 연결은 유지하고, 에셋에 저장한 로컬 스크립트·프로퍼티 재정의·제거 기록은 인스턴스에서 비워 원본 갱신을 받는다. 내부 바인딩은 원본의 경로로 해석하며 외부에서 들어오는 ID 참조는 그대로 유지한다.

GUI AssetOperations의 배치 트랜잭션으로 에셋 생성과 레벨 연결을 하나의 Undo/Redo로 묶는다. 실패하면 연결과 생성을 함께 복원한다. GUI는 레벨을 미저장 상태로 두고, CLI prefab.create의 --link는 같은 캡처·연결 로직을 사용한 뒤 레벨도 저장한다. CLI의 기존 캡처만 수행하는 사용법은 유지한다. 중간 실패 시 생성한 에셋을 제거하고 외부에서 바뀐 레벨을 덮어쓰지 않는다.

```text
Create Prefab (GUI / CLI)
├ Prefab 에셋 ← 캡처한 계층·스크립트·값
└ 기존 루트 LObject ─ 원본 참조 → 새 Prefab 에셋
  └ 기존 자손 LObject (ID·부모·Transform 유지)
```

## 결과

- 긍정: 재배치 없이 원본 편집 흐름으로 전환하고 내부·외부 참조를 유지한다.
- 부정: GUI에서는 에셋 저장과 별도로 레벨 저장이 필요하다. 상속 자손 하나를 교체하는 동작은 허용하지 않는다.
- 중립: 저장 형식은 그대로이며 캡처만 필요한 CLI 작업은 --link를 생략한다.
