# 0005. 프로젝트 생성 시 JSON 기본 레벨 저장

- 상태: 채택
- 날짜: 2026-10-08
- 확장: [ADR 0002](0002-project-launcher-and-assets.md)의 프로젝트 초기 파일 구성

## 배경과 제약

새 프로젝트에 기본 Level 파일을 생성하도록 요청받았다. 기존 Level은 이미 버전이 있는 JSON 형식으로 저장되므로 별도 직렬화 형식을 만들 필요가 없다. 새 프로젝트 생성은 기존 파일을 덮어쓰지 않아야 하며 한글 프로젝트 경로와 생성 실패 시 정리를 유지해야 한다.

## 대안과 판단 기준

- 새 `.json` 확장자로 별도 형식을 만들면 기존 `.level` 저장·검증 코드와 중복된다.
- 기존 `.level` 확장자와 JSON 인코더를 재사용하면 에셋 종류를 구분하고 기존 Level 로딩·편집 형식을 유지할 수 있다.
- 빈 `Assets`만 만들면 Git이 디렉터리를 보존하지 않는다. 기본 레벨 파일을 포함하면 별도 숨김 파일이나 ignore 예외 없이 폴더 구조를 보존할 수 있다.

## 결정 및 근거

프로젝트 생성 시 `Assets/Levels/Default.level`을 저장한다. 내용은 기존 `LevelFile.encode(Level.new())`가 생성하는 JSON이며 `formatVersion: 1`, `lobjects: []`를 갖는 빈 Level이다. 경로는 프로젝트 기준 상대 경로로 정의한다.

JSON은 폴더를 만들기 전에 완성하고, 파일 생성은 Unicode 호스트 파일시스템의 기존 파일 덮어쓰기 금지 방식을 사용한다. 기본 레벨과 프로젝트 정보 파일 중 어느 쪽이 실패해도 이번 작업에서 만든 파일·빈 디렉터리만 역순으로 정리한다. 열린 기존 프로젝트에는 기본 레벨을 자동으로 생성하거나 덮어쓰지 않는다.

## 예상 결과

- 긍정: 새 프로젝트에 편집 가능한 기본 레벨 에셋이 생기고, 테스트 프로젝트의 Assets 구조도 Git에 파일로 보존할 수 있다.
- 부정: 프로젝트 생성에 추가 폴더·파일 쓰기가 필요하므로 중간 실패를 정리해야 한다.
- 중립: 기본 레벨은 비어 있으며 LObject 데이터 형식과 Edit/Runtime 분리는 유지한다.
