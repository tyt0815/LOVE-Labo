# 0065. 오류 발생과 오류 표시를 분리한다

- 상태: 승인·구현
- 대체: [0064](0064-persistent-latest-log-and-overlay.md)의 오류 표시 프레임별 기록. 레이아웃·행 간격·중복 오류 보존은 유지한다.

## 배경과 제약

오류 표시 상태는 여러 프레임 동안 유지된다. draw에서 이 상태를 기록하면 드롭 한 번으로 동일 로그가 여러 개 생긴다. 메시지 문자열 비교로 중복 제거하면 같은 동작이 다시 실패한 경우도 누락된다. 기존 패널의 오류 표시와 문자열 필드 사용은 유지해야 한다.

## 대안과 판단 기준

프레임별 기록은 발생 횟수를 과장하고 문자열 중복 제거는 실제 반복 실패를 잃는다. 모든 오류 대입을 새 setter로 교체하는 방식은 여러 패널의 기존 표시 코드를 함께 바꿔야 한다. 기존 대입을 발생 이벤트로 관찰하는 공용 모듈을 사용하여 표시와 기록을 분리한다.

## 결정과 근거

EditorApp은 ErrorLog를 통해 자신과 관련 패널의 오류 필드를 관찰한다. 오류 필드에 값이 대입되면 DebugSession에 한 줄을 추가하며 같은 값의 재대입도 새 발생으로 기록한다. nil 대입은 표시 상태만 지운다. draw는 오류를 기록하지 않는다.

이미 기록한 오류를 복원하는 경우에는 `ErrorLog.restore(target, field, value)`로 표시 상태만 갱신한다. 예를 들어 Refresh에서 실패한 폴더 대신 루트 폴더를 연 뒤 원래 오류를 복원하는 것은 새 실패가 아니다. 일반 대입과 복원을 명시적으로 구분하므로 별도 사용자 동작에서 같은 오류가 다시 발생하면 새 기록은 유지된다.

ErrorLog는 인스턴스 메타테이블의 기존 동작을 유지하면서 해당 필드의 읽기·쓰기를 연결한다. 초기 오류는 연결 시 한 번 기록하고 같은 객체·필드를 중복 연결하지 않는다. 관찰 대상은 직렬화하지 않는 에디터 상태이며 런타임 오브젝트·스크립트 데이터에는 적용하지 않는다.

```text
EditorApp ──의존──> ErrorLog ──기록──> DebugSession
                      └─관찰: 에디터·패널의 오류 필드 대입
```

## 결과

- 긍정: 한 번의 실패는 한 줄로 기록하며 반복 실패는 빠짐없이 남긴다. 화면 갱신 횟수와 로그 수가 분리된다.
- 부정: 관찰 필드는 rawget·pairs 대상이 아닌 별도 상태로 관리되므로 직접 필드 접근을 사용해야 한다.
- 중립: 오류 표시 문구·색, 최근 1,000개 보관 한계와 로그 API는 유지한다.
