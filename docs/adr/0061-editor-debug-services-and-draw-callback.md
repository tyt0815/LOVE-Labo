# 0061. 에디터 디버그 서비스와 편집 표시 콜백

- 상태: 승인·구현
- 최신 로그 유지와 기록 패널 표시 변경: [0064](0064-persistent-latest-log-and-overlay.md).
- 관련: [0058](0058-plugins-and-mounted-assets.md), [0060](0060-isolated-live-previews-and-saved-thumbnails.md)

## 배경과 제약

게임 코드에서 로그와 일시적인 도형을 출력하고 편집 중에도 카메라 영역 등의 표시를 확장해야 한다. 배포 게임은 같은 코드를 실행할 수 있어야 하지만 에디터의 기록·표시 구현을 포함하면 안 된다. 미리보기는 게임 생명주기를 실행하지 않는다.

## 대안과 판단 기준

전역 디버그 서비스는 여러 World·미리보기의 기록이 섞이며 배포에도 구현이 유입되기 쉽다. draw 안에서 편집 표시를 함께 실행하면 게임 화면에도 표시되고 런타임 전용 상태에 의존한다. World별 서비스 주입과 별도 콜백을 선택한다.

## 결정과 근거

World.debug의 기본값은 core.Debug의 no-op API다. Editor Play와 level.simulate --debug에만 editor.DebugSession을 초기화 전에 주입하며 레벨 전환에도 전달한다. 실제 로그·화면 로그·도형 보관과 렌더링은 editor 모듈에 두고 게임 Export에서 제외한다. API 호출의 인자 계산 자체는 일반 Lua 실행으로 남는다.

화면 로그는 최신순이고 key가 같으면 교체 후 맨 앞으로 이동한다. 색은 RGB 0–255, 기본 주황색이다. lifespan 0은 다음 표시 프레임 한 번이며, 양수는 초 단위다. 하단 로그는 최근 1,000개를 보관하며 접혔을 때 최신 로그를 5초 표시한다. 긴 문자열은 한 행에 맞게 줄임표를 사용한다.

Script.drawEditor(context)는 Scene View의 준비 스크립트에만 호출한다. beginPlay/update 없이 프로퍼티로 표시를 계산해야 한다. context는 월드 좌표 도형 API, selected와 테마 color를 제공한다. 카메라 범위 표시도 Camera 플러그인이 이 콜백을 구현한다. 편집 표시와 Play 디버그 도형은 같은 그리기 도구를 사용하되 실행 시점과 보관 수명은 분리한다.

## 결과

- 긍정: 배포 안전성, World별 격리, CLI/GUI 공용 검증, 플러그인에서 편집 표시 확장.
- 부정: 배포에서는 인자를 계산하는 비용까지 사라지지는 않는다. 로그가 1,000개를 넘으면 오래된 기록을 버린다.
- 중립: drawEditor 함수 자체는 Lua 소스에 남지만 독립 실행 Host는 호출하지 않는다. 추가적인 게임 스크립트를 코어에 제공하지 않는다.
