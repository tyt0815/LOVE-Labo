# 0011. 에셋 ID·메타데이터와 프로젝트 경로 캐시

- 상태: 채택
- 날짜: 2026-10-08
- 부분 대체: [ADR 0007](0007-sources-and-level-scripts.md)·[ADR 0010](0010-script-types-and-prefab-creation.md)의 경로 참조와 스크립트 종류의 원본

## 배경과 제약

Level·Prefab이 스크립트를 경로로 참조하면 이동·이름 변경 때 모든 의존 파일을 다시 써야 한다. 사용자는 파일별 `.meta`에 고유 ID를 보관하고 Assets·Sources 전체의 ID와 현재 경로를 하나의 재생성 가능한 목록으로 관리하는 방식을 선택했다. 기존 프로젝트와 한글 경로를 지원하며 목록 재생성이나 파일 이동이 ID를 바꾸면 안 된다.

## 대안과 판단 기준

- 경로 참조를 일괄 수정하면 열린 문서와 디스크 데이터의 동기화가 복잡하고 이동마다 많은 파일을 쓴다.
- ID 원본을 하나의 인덱스에만 두면 인덱스 유실·손상이 파일 정체성의 유실로 이어진다.
- Assets·Sources별 인덱스를 나누면 두 루트에 걸친 참조를 찾을 때 양쪽 목록을 관리해야 한다.
- 파일별 ID 원본과 단일 프로젝트 경로 캐시를 분리하면 경로만 바꿔도 참조를 유지하고 캐시를 다시 만들 수 있다.

## 결정 및 근거

1. Assets·Sources의 일반 파일마다 `<원본 파일명>.meta`를 둔다. `version: 1`과 소문자 UUID `id`가 파일 정체성의 원본이다. Lua 메타는 `scriptKind: level | lobject`도 보관한다. 폴더 자체에는 ID를 부여하지 않는다. 폴더 이동 시 모든 원본과 메타가 함께 이동한다.
2. 메타가 없는 파일을 프로젝트 열기·Refresh에서 가져온다. Lua의 기존 첫 줄 표식은 최초 가져오기 때 종류를 결정하는 힌트이며 표식 없는 기존 Lua는 Level로 분류한다. 메타가 생성된 뒤에는 그 종류가 원본이다. Lua 코드를 실행해서 종류를 찾지 않는다.
3. 기존 메타를 전체 검증한 뒤 누락된 메타를 생성한다. 잘못된 메타, 링크인 메타, 중복 ID는 오류다. 복사된 메타의 중복 ID를 자동으로 바꾸거나 손상된 메타를 새 ID로 덮어쓰지 않는다. 원본 없이 남은 메타는 인덱스에서 제외하되 임의로 삭제하지 않는다.
4. 프로젝트 루트의 `asset-index.json`은 `version: 1`, `paths: {ID: 현재 상대 경로}`인 캐시다. 시작·Refresh·생성·삭제·이동 때 메타를 스캔하여 복원한다. 기존 캐시 내용은 참조의 원본으로 읽지 않는다. 캐시가 없거나 손상돼도 같은 ID로 재생성한다. 캐시 쓰기가 실패하면 메모리 목록을 사용하고 오류를 브라우저에 표시한다.
5. `project.labo`의 `defaultLevelReference`, Level의 `scriptReference`·배치 LObject의 `definitionReference`, Prefab의 `definitionReference`는 알려진 파일의 ID를 저장한다. 새 프로젝트·Level·Prefab 형식은 버전 2다. 버전 1도 읽고, 등록된 경로 참조를 가져오기 시 ID로 전환한다. 존재하지 않는 파일의 경로나 기존 임의 Definition 이름은 추측으로 새 ID를 만들지 않고 그대로 둔다.
6. 파일 전환은 파일별 임시 파일과 Windows 교체 API로 정상 원본을 보존한다. 여러 파일의 마이그레이션 전체가 하나의 원자적 거래는 아니다. 실패 후 재시도해도 이미 생성한 메타 ID는 유지하며 완료된 ID 참조는 다시 변경하지 않는다.
7. 에디터의 Move / Rename에서 원본과 메타를 함께 옮긴다. 대상 부모는 같은 Assets·Sources 루트의 기존 일반 폴더여야 하고, 원본 확장자를 유지한다. 덮어쓰기·루트 이동·자기 하위로 이동·메타 단독 이동은 거부한다. 파일 이동 중 실패하면 복원을 시도한다. `asset-move.json`에 작업과 ID를 기록해 두 rename 사이에 종료돼도 다음 열기·Refresh에서 메타를 새 위치로 복구할 수 있게 한다. 상태가 모호하면 임의로 새 ID를 부여하지 않고 오류로 중단한다.
8. 이미 ID로 참조하는 의존 Level·Prefab은 이동 때 다시 쓰지 않는다. 열린 문서는 파일 ID로 새 저장 경로를 찾고, UI 이동 후에도 편집 데이터와 dirty 상태를 유지한다. 파일 삭제는 메타도 함께 삭제하고 인덱스에서 제거한다. 삭제한 ID를 참조하는 다른 파일을 자동으로 수정하거나 다른 파일의 ID로 대체하지 않는다.
9. `.meta`는 원본과 함께 Git에 보관한다. 인덱스와 이동 기록은 캐시·임시 파일이므로 저장소에서 제외한다. 프로젝트 브라우저는 메타·저장 임시 파일을 숨긴다. 외부 도구에서 이동할 때도 원본과 메타를 함께 옮긴 뒤 Refresh한다. 메타를 잃거나 원본만 이동하면 같은 정체성을 보장할 수 없다.

## 예상 결과

- 긍정: 이동·이름 변경에도 에셋 참조가 유지되고, 캐시 유실은 ID 유실로 이어지지 않는다. 기존 파일의 경로 참조를 점진적으로 가져올 수 있다.
- 부정: 원본과 함께 관리할 메타 파일이 늘어나며 중복·손상된 메타를 해결해야 한다. 외부 파일 변경과의 완전한 원자성은 제공하지 않는다.
- 중립: 인덱스는 의존성 그래프를 중복 저장하지 않는다. 참조의 원본은 Level·Prefab이고, ID 원본은 메타이며, 현재 위치만 캐시에 둔다. Prefab 편집·배치와 Runtime Definition 바인딩은 이번 작업에서 확장하지 않는다.
