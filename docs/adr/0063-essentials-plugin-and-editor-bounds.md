# 0063. 기본 기능 플러그인 통합과 편집 영역 표시

- 상태: 승인·구현
- 변경: [0058](0058-plugins-and-mounted-assets.md)의 스크립트별 플러그인 분할. [0061](0061-editor-debug-services-and-draw-callback.md)의 편집 표시 계약을 사용한다.

## 배경과 제약

기본 기능 다섯 개를 개별 플러그인으로 관리하는 것은 현재 규모에서 불필요하게 잘게 나뉜다. 그림이 없는 클릭·UI 영역도 편집 중 시각적으로 확인해야 하지만 PIE와 배포 화면에는 표시하면 안 된다.

## 대안과 판단 기준

개별 플러그인을 유지하는 대안은 선택성이 높지만 관리 비용이 크다. Core로 옮기면 기본 기능을 플러그인으로 제공한다는 원칙을 어긴다. 하나의 기능 묶음으로 제공하고 실제 사용은 스크립트 부착으로 선택한다.

## 결정과 근거

LaboEssentials에 Camera·Sprite·Pointer·RectBounds·Canvas를 포함한다. Rect는 렌더러가 아니라 사각형 영역 제공자이므로 RectBounds로 이름을 바꾼다. 새 부착 목록은 새 이름을 사용하고 기존 Rect 별칭은 읽기 호환성으로 유지한다. 스크립트의 UUID를 보존하며 기존 활성 설정·사용자 의존성과 제공 스크립트 경로를 새 묶음으로 해석한다. 새 프로젝트는 계속 아무 플러그인도 활성화하지 않는다.

관리 목록은 이름 위주의 접힌 행으로 표시한다. 의존성은 왼쪽 화살표로 펼치며 비활성 의존성은 주황색 !, 누락·순환 의존성은 빨간색 !로 표시한다. 오류는 독립적인 3줄 높이 스크롤 영역에서 확인한다.

각 영역 스크립트가 drawEditor를 구현한다. 에디터 context는 이미지 조회와 bounds 도형 생성을 제공하고 월드 Transform으로 모서리를 합성한다. Pointer는 참조한 실제 boundsSource를 사용하며 Sprite는 이미지 크기, Canvas는 편집 시 설정된 영역을 사용한다. PIE에서는 GameView의 draw만 사용하므로 이 콜백을 실행하지 않는다.

## 결과

- 긍정: 플러그인 목록 단순화, 보이지 않는 영역 확인, 기존 부착·ID 호환성.
- 부정: 다섯 스크립트는 함께 활성화한다. 과거 제공 플러그인 이름을 일부 사용한 프로젝트도 전체 묶음이 활성화된다.
- 중립: 게임 렌더링·입력 판정의 의미는 그대로이며 편집 경계 표시는 gameplay draw에 포함되지 않는다.
