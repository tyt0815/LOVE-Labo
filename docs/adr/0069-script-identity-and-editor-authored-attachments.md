# 0069. 스크립트 부착 식별자와 편집 구성 및 활성 상태

- 상태: 승인·구현
- 초기화 콜백 명칭은 [ADR 0070](0070-load-lifecycle-callback.md)의 load로 통일한다.
- 부분 대체: [0050](0050-attached-scripts-and-unified-assets.md), [0052](0052-local-scripts-and-fixed-inherited-topology.md)의 런타임 부착·제거 API

## 배경과 제약

스크립트 부착 이름을 저장 참조의 식별자로 사용하면 이름 변경이 프로퍼티 재정의와 다른 스크립트의 참조를 깨뜨린다. 사용자는 이름과 내부 ID를 분리하고 게임 중 부착 구성 변경 대신 활성 상태를 제어하기로 결정했다. 편집기의 인스턴스 로컬 부착과 Prefab 상속 구조 제한은 유지한다.

## 대안과 판단 기준

이름을 곧 ID로 사용하는 방식은 단순하지만 이름 변경 시 모든 저장 참조를 찾아 수정해야 한다. ID만 제공하면 코드와 Inspector에서 부착을 구분하기 어렵다. 하나의 조회 함수에서 이름·ID·클래스를 추측하면 모호성이 생긴다. 독립 UUID와 이름을 함께 저장하고 명시적인 조회 함수를 제공하는 방식을 선택한다.

동적 부착 API를 유지하는 대안 대신 에디터가 실행 구성을 작성하고 게임은 enabled로 실행 여부를 바꾸는 모델을 선택한다. 내부 로더의 부착 기능은 필요하지만 공개 Engine API로 제공하지 않는다.

## 결정과 근거

새 부착은 `{id = UUID, name = 사용자이름, source = 원본참조}`로 저장한다. 이름은 같은 LObject 안에서 고유하다. 예전 식별자는 읽기 호환성을 유지한다. 스크립트 참조와 Main Camera, 재정의 키는 ID를 사용한다. 상속된 이름 변경은 source를 고정하지 않는 `{id, name}` 부분 레코드로 저장한다.

LObject는 getScriptByName, getScriptById, getScriptByClass, getScriptsByClass를 제공한다. 클래스 조회에는 파생 클래스도 포함하며 부착 순서대로 반환한다. 단일 조회 실패는 nil, 복수 조회 실패는 빈 목록이다. 공개 addScript/removeScript/getScript는 제공하지 않는다.

같은 프로젝트 로더 안에서 일반 require와 부착 클래스 로딩은 모듈 테이블 캐시를 공유한다. 사용자 Lua 클래스를 require로 가져와 조회해도 실제 부착 클래스와 같은 테이블로 비교한다. 보조 모듈은 부착하지 않는 한 기존 일반 모듈 동작을 유지한다.

World 준비 시 한 로더를 생성해 레벨 클래스·부착 구성·이후 Spawn에 전달한다. 레벨 콜백의 require도 같은 캐시를 사용한다. 캐시는 World 준비 범위에 한정하며 새 World를 준비할 때 소스를 다시 읽는다. draw 후보 목록의 활성 필터 외에 각 호출 직전에도 enabled를 검사하여 앞선 콜백의 비활성화가 같은 프레임에 적용되도록 한다.

모든 Script에는 enabled=true가 있다. false는 update·draw·포인터 입력을 중단하며 카메라 선택에서 제외한다. load는 초기화를 위해 한 번 실행한다. Canvas는 비활성화되어도 자손의 좌표계 정의를 유지한다. 비활성 포인터의 캡처는 다음 입력 처리 시 해제한다.

편집·로딩 구성은 내부 ScriptRuntime에 분리한다. 독립 로컬 부착을 복제하면 새 UUID를 발급하고 복제 범위의 스크립트 참조를 재연결한다. 원본 Prefab에서 상속한 부착은 원본 ID를 유지한다. Prefab 캡처·원본 연결은 기존 부착 ID를 보존하여 기존 인스턴스 참조를 유지한다.

CLI의 프로퍼티 입출력에는 사용자 이름을 표시하고 scriptIds로 내부 ID를 확인할 수 있다. 편집 인자는 이름·ID를 모두 지원하며 저장은 ID로 정규화한다. Inspector 헤더는 원본 찾기·로컬 제거 버튼과 Rename·Copy ID 우클릭 메뉴를 제공한다.

## 결과

- 긍정: 이름 변경과 저장 참조가 분리되고 상속 이름 변경이 원본 갱신을 유지한다. 게임 코드는 명시적인 조회와 활성 제어에 집중한다.
- 부정: 이전 런타임 동적 부착 코드는 에디터 구성 또는 Prefab 생성과 enabled 제어로 전환해야 한다. 이름을 코드에 직접 쓴 경우 이름 변경 시 코드도 수정해야 한다.
- 중립: LObject·Script 명칭과 포함 관계, Prefab 상속 구조 제한은 유지한다. UUID는 식별용이며 접근 제한이나 보안 기능이 아니다.
