# 0058. 기능 스크립트는 플러그인으로 제공하고 모든 에셋을 마운트한다

- 상태: 승인·구현
- 제공 플러그인 분할 변경: [0063](0063-essentials-plugin-and-editor-bounds.md).
- 탐색 표시 계층 변경: [0062](0062-plugin-browser-roots.md). 아래 Assets 하위 표시 결정은 같은 깊이의 탐색 루트로 대체한다.
- 변경: [0050](0050-attached-scripts-and-unified-assets.md)의 Core 편의 스크립트 제공 위치. LObject·Script 부착 모델은 유지한다.

## 배경과 제약

사용자는 기본 제공 스크립트 없이 LObject와 기반 API만 있는 환경을 원한다. Camera·Sprite를 비롯한 향후 기능 스크립트는 선택 가능한 플러그인으로 제공한다. 플러그인은 Lua에 한정하지 않고 모든 지원 에셋과 폴더를 포함해야 한다. 편집·CLI·배포 게임의 참조 ID 계약을 유지해야 한다.

## 대안과 판단 기준

Core에 편의 스크립트를 유지하거나 플러그인 파일을 Assets로 복사하는 방식을 검토했다. 선택적 기능 제공과 출처 보존을 위해 마운트를 택했다. 단일 Plugins 폴더와 출처별 폴더를 비교했으며, 중간 폴더를 추가하지 않고 제공·사용자 플러그인을 구분한다.

## 결정과 근거

Core는 LObject·Script 생명주기와 Transform·Bounds·카메라 및 입력 실행 API를 제공한다. Camera·Sprite·Pointer·Rect·Canvas 구현은 src/plugins의 플러그인이다. 새 프로젝트의 plugins.json은 활성 목록이 비어 있다. 기존 설정 없는 프로젝트는 기존 참조를 유지하기 위해 이전 편의 플러그인을 활성 상태로 해석한다.

사용자 플러그인은 프로젝트 Plugins/<이름>에 plugin.json과 Assets를 가진다. 활성 플러그인의 에셋은 Assets/Labo Plugins/<이름> 또는 Assets/User Plugins/<이름>에 표시한다. Labo는 읽기 전용, User는 일반 에셋처럼 생성·추가·편집·이동·삭제를 지원한다. 플러그인 루트의 이동·삭제는 관리 창에서 처리하며 비활성화는 파일을 삭제하지 않는다. Labo 에셋은 프로젝트 .labo/PluginCache에 캐시하여 패키징된 에디터에서도 공용 파일 읽기를 지원한다.

의존 플러그인은 먼저 활성화한다. 필요한 비활성 플러그인을 함께 켜는 경우 목록과 확인창을 표시한다. 비활성화도 활성 의존자의 목록을 함께 확인한다. 누락·순환 의존성은 거절하고 기존 설정을 유지한다. 사용 중인 프로젝트 참조를 깨뜨리는 비활성화는 사용처 오류와 함께 거절한다. 설정 변경 실패 시 이전 설정을 복원한다.

의존성 표시는 활성 회색, 비활성 주황색, 미설치 빨간색과 상태 문구를 함께 사용한다. 등록 스크립트의 ID를 기록해 이름 변경 후에도 별칭·상속·부착을 유지한다. Export는 활성 플러그인의 정의와 모든 마운트 에셋을 포함하고, 독립 게임은 같은 레지스트리와 로더를 사용한다.

## 결과

- 긍정: 기본 환경의 선택권, 출처와 수정 권한 구분, 모든 에셋 형식에 공통 탐색·ID·Export 계약을 적용한다.
- 부정: 설정·의존성 검증과 제공 에셋 캐시 관리가 추가된다. 사용 중인 플러그인을 끄려면 참조를 먼저 정리해야 한다.
- 중립: 플러그인 버전 제약·배포 다운로드·핫 리로드는 이번 요구에 포함하지 않는다. 기반 Script API는 플러그인 없이도 사용자 코드를 실행한다.
