# 0059. 스크립트 배치와 외부 에셋 복사 임포트

- 상태: 승인·구현
- 관련: [0050](0050-attached-scripts-and-unified-assets.md), [0058](0058-plugins-and-mounted-assets.md)

## 배경과 제약

사용자는 Prefab 외에 스크립트도 계층·뷰포트에 배치하고 외부 파일 탐색기에서 에셋을 가져오기를 요청했다. Inspector 대상 전환 예외는 추가하지 않으며 플러그인 권한·ID·Undo 계약을 유지한다.

## 대안과 판단 기준

Lua를 오브젝트 템플릿으로 취급하는 대신 빈 LObject를 만들고 하나의 스크립트를 부착한다. 임포트는 외부 파일 이동·덮어쓰기보다 원본 보존과 충돌 거절을 선택한다.

## 결정과 근거

ScriptPlacement는 GUI와 instance.add --script가 공유한다. 오브젝트 스크립트만 허용하고 이름에 순번을 붙인다. Prefab과 script 인자는 동시에 지정하지 않는다. 다중 드롭 실패 시 전체 배치를 복원한다.

AssetImport는 GUI와 asset.import의 공용 파일·폴더 복사 로직이다. 새 ID를 발급하고 외부 .meta를 가져오지 않는다. 충돌과 링크를 거절하며 실패 시 이번 복사만 정리한다. GUI 임포트는 기존 생성 이력 저장을 공유하여 Undo/Redo한다. User 플러그인은 일반 대상이며 Labo 플러그인은 읽기 전용이다.

## 결과

- 긍정: Lua 부착 모델 유지, GUI·CLI 공용 검증, 원본 보존과 복구 가능한 편집.
- 부정: 다른 프로젝트의 Prefab을 가져오면 기존 외부 에셋 ID 참조는 수동으로 다시 지정해야 한다.
- 중립: 시작 화면의 폴더 드롭은 기존 프로젝트 열기 기능을 유지한다.
