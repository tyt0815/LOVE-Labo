# 0029. 제품 소스와 번들 리소스를 src로 통합

- 상태: 채택
- 날짜: 2026-10-09
- 확장: [ADR 0027](0027-windows-editor-packaging.md), [ADR 0028](0028-agent-cli-and-standalone-game-export.md)의 빌드 입력 경로

## 배경과 제약

에디터·Core·공용 프로젝트 로더·런타임 폴더가 저장소 루트에 흩어져 개발 도구·문서·테스트와 구분하기 어렵다. 사용자는 제품 소스를 한 폴더에 모으기를 요청했다. 사용자 게임의 `Sources`와 구분하며 모듈 이름·패키지 형식·프로젝트 경로 기준은 유지한다.

## 대안과 판단 기준

- `Sources`는 사용자 게임 프로젝트와 이름이 같아 혼동을 만든다. 제품 소스는 통상적인 `src`로 구분한다.
- 소스 이동 후 루트에 main/conf 위임 파일을 남기면 두 실행 루트의 설정·리소스 규칙을 유지해야 한다. 개발 실행 루트 자체를 `src`로 정한다.
- 테스트까지 `src`로 옮기면 배포 제외 규칙과 제품/개발 경계가 흐려진다. 테스트는 루트에 유지하고 `--test`에서만 제한된 `tests.*` 네이티브 파일 로더를 연결한다. LÖVE 가상 파일 시스템 밖의 폴더 마운트 제약을 피한다.
- 기존 ADR의 파일 위치는 당시의 기록이므로 일괄 재작성하지 않는다. 현재 사용법·빌드 스크립트·개발 지침만 갱신한다.

## 결정 및 근거

1. `main.lua`, `conf.lua`, `engine.lua`, `core/`, `editor/`, `project/`, `runtime/`과 폰트·테마·개발 설정을 `src/` 아래로 옮긴다. 컴포넌트 사용 문서는 `docs/components.md`로 옮긴다.
2. 개발 실행은 저장소에서 `love src`, 테스트는 `love src --test`이다. 내부 `require("core.world")` 등의 모듈 이름과 `editor/fonts/...` 가상 경로는 유지한다. 사용자 프로젝트의 상대 `--project` 경로는 실행 명령의 작업 디렉터리를 계속 기준으로 한다.
3. 패키징 스크립트는 `src`를 입력으로 삼되 그 내용물을 `.love` 루트에 넣는다. 배포 파일·외부 설정 위치·게임 Export 내부 경로는 변경하지 않는다.
4. 테스트 로더는 `--test`에서만 루트의 `tests.*` 이름을 허용하고 저장소의 파일을 읽는다. 정상 실행·CLI·게임 배포에는 이 로더를 연결하지 않는다. 테스트 진입 오류는 오류 창에서 기다리지 않고 실패 종료 코드를 반환한다.

## 결과와 관계

```text
저장소
├─ src/      제품 소스·번들 리소스 포함
│  ├─ core/  런타임
│  ├─ editor/ UI·CLI·Export
│  ├─ project/ 공용 로딩·데이터
│  └─ runtime/ 게임 호스트·어댑터
├─ tests/    개발 테스트·샘플 프로젝트 포함
├─ docs/     문서·ADR 포함
├─ scripts/  빌드·검증 자동화 포함
└─ build/    생성물 포함
```

포함 경계만 바뀌며 상속이나 모듈 사이의 의존 관계는 바꾸지 않는다.

- 긍정: 제품과 개발 파일의 구분이 명확하고 패키징 입력 루트가 단일해진다.
- 부정: 개발 실행 명령과 파일 링크가 바뀐다. 테스트는 Windows 네이티브 파일 로더로 저장소 경로를 읽는다.
- 중립: 사용자 프로젝트 구조·직렬화·게임 및 에디터 배포물의 내부 경로·에디터 동작은 유지한다.
