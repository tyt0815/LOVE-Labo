# 0027. Windows 에디터 패키징과 외부 설정

- 상태: 채택
- 날짜: 2026-10-09
- 부분 대체: [ADR 0009](0009-editor-settings-and-themes.md)의 배포 시 설정 위치
- 유지: 설계 문서의 게임 Export는 에디터에 의존하지 않는 별도 런타임 패키지

## 배경과 제약

사용자는 에디터 소스를 설치 폴더에 풀어 놓지 않고 배포하며 설정은 외부에서 수정하기를 원한다. 정식 배포 도구·게임 Export·AI CLI에 앞서 기존 에디터가 패키지에서 동작하는지 검증한다. Windows·LÖVE 11.5 및 기존 외부 프로젝트 파일 시스템·클래스/에셋 ID 계약을 유지한다.

## 대안과 판단 기준

- 소스 폴더를 그대로 복사하는 방식은 사용자의 배포 요구를 충족하지 못한다.
- 바이트코드·난독화·별도 네이티브 호스트는 초기 검증의 범위를 넘고 실행 환경 제약을 늘린다.
- 전체 저장소 ZIP은 테스트·사용자 프로젝트·개발 파일까지 배포한다. 명시한 루트 파일과 Core·Editor Lua, 폰트만 포함한다.
- 설치 디렉터리를 가상 파일 시스템에 통째로 마운트하면 설정 외 파일도 노출된다. fused 실행의 Theme만 네이티브 파일 읽기로 실행 파일 옆 설정·테마에 접근한다.

## 결정 및 근거

1. PowerShell 스크립트는 LÖVE 11.5를 확인하고 `.love` ZIP을 만든 뒤 `love.exe`에 바이트 스트림으로 결합한다. 같은 배포판의 DLL과 라이선스를 함께 복사한다. Lua 원문은 패키지 안에 있으며 추출을 막는 보호 방식은 아니다.
2. `settings.json`과 `themes/*.json`은 실행 파일 옆에 둔다. 다시 패키징할 때 기존 사용자 설정은 보존한다. 소스 실행은 기존 설정 경로를 유지하며 스냅 설정은 사용자 저장 폴더를 유지한다.
3. `main`은 `--verify-package`에서 PackageVerification을 호출한다. 이 모듈은 Project·EditorApp·Theme 등 기존 생성/편집 로직에 의존하며 자체 생성한 외부 프로젝트로 저장·런타임·UI를 확인하고 JSON 결과와 화면을 기록한다. 상속 관계를 추가하지 않는다.
4. 배포 검증은 실제 fused 실행 파일을 실행한다. 테스트 코드·샘플 프로젝트·외부 설정이 패키지에 섞이지 않았는지도 검사한다. 검증 데이터는 배포 폴더 밖의 새 폴더에만 만든다.

## 예상 결과

- 긍정: 재현 가능한 패키징 명령으로 외부 파일 경로·프로젝트 코드·폰트·설정의 배포 동작을 조기에 확인한다.
- 부정: Windows 런타임 설치가 필요하고, 추가 배포 리소스가 생기면 포함 목록을 갱신해야 한다. 설정·스냅 저장 위치는 실행 방식에 따라 달라질 수 있다.
- 중립: Core·프로젝트 스키마·에셋 ID·직렬화는 변경하지 않는다. 게임 Export·일반 CLI·설치 프로그램·소스 보호는 이후 작업이다.
