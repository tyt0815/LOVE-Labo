# 0066. 중앙 에셋 목록과 검토 후 참조 복구

- 상태: 승인·구현
- 대체: [0011](0011-asset-ids-metadata-and-path-cache.md)의 파일별 메타와 경로 캐시.
- 확장: [0031](0031-asset-operation-history.md)의 ID 유지 이력, [0058](0058-plugins-and-mounted-assets.md)의 플러그인 메타 관리.

## 배경과 제약

파일별 `.meta`는 외부 소스 편집을 번거롭게 한다. 프로젝트와 플러그인이 같은 파일명으로 메타를 관리하고 외부 이동은 검토 후 복구한다. 기존 ID·Prefab·레벨 참조와 Undo/Redo·Export를 유지해야 한다. 같은 이름·내용이 여럿이면 추측해서 연결하지 않는다.

## 대안과 판단 기준

VS Code에서 메타를 숨기는 방식은 파일 수와 이중 관리 문제를 남긴다. plugin.json에 ID를 넣으면 프로젝트와 다른 구조가 된다. 파일명만으로 자동 복구하면 오연결 위험이 있다. 소유 범위별 중앙 목록, 내용 해시 기반 추천과 수동 선택을 채택한다.

## 결정과 근거

프로젝트·플러그인 루트의 `assets.json`이 `{version: 1, assets: {경로: 메타}}`로 ID·Lua 종류·최근 확인 내용 해시를 저장한다. 공개 스크립트의 안정적인 별칭은 scriptName에 기록한다. plugin.json은 이름·의존성·공개 스크립트의 파일 연결만 관리한다. 이동한 공개 스크립트는 별칭으로 중앙 목록에서 기존 ID를 찾는다. Export는 동일 메타를 포함한다.

기존 메타·scriptIds를 검증해 ID를 목록에 보존한 뒤 `.meta`를 제거한다. 비활성 사용자 플러그인도 이전하며 파일이 없는 메타는 끊어진 등록으로 보존한다. Labo 원본은 저장소에서 전환하고 에디터에서는 읽기 전용으로 유지한다. asset-index.json 캐시는 제거한다.

생성·임포트·이동·삭제·Undo는 AssetCatalog로 목록을 갱신한다. 목록 쓰기 실패 시 이동을 복구한다. 해당 소유 범위에 끊어진 등록이 있으면 외부의 새 파일은 복구 후보로 보존하고, 없으면 새 ID를 발급한다.

Project 메뉴에 Refresh·Plugins·Export를 둔다. Open Project와 별도 Repair 메뉴는 추가하지 않는다. Refresh는 미저장 문서를 유지해 목록·화면·캐시를 갱신하고 문제가 있으면 복구 창을 연다. 브라우저의 Refresh 버튼은 제거한다. Sources를 다시 분리하지 않으며 프로젝트 이름 아래 Assets를 표시한다. 플러그인 표시 그룹과 내부 경로는 유지한다.

복구 창은 체크박스와 펼치는 파일 트리를 사용한다. 같은 소유 범위·확장자의 미등록 파일 중 해시가 유일하게 일치하면 추천 대상을 체크한다. 애매한 후보는 수동 선택하며 같은 파일을 여러 ID에 연결하지 않는다. 적용 직전 계획 revision·파일 상태를 검사한다. Delete는 사라진 등록만 제거하고 사용 중인 ID는 사용처와 함께 거부한다. 후보 파일은 삭제하지 않는다. 브라우저의 끊어진 파일은 빨간 이름·!로 표시하며 더블클릭으로 같은 창을 연다.

```text
Project·AssetOperations ──의존──> AssetCatalog ──저장──> assets.json
Refresh·CLI ──의존──> AssetRepair ──의존──> AssetCatalog
AssetRepairDialog ──포함──> AssetPickerTree·Scrollbar
PluginRegistry ──참조──> 플러그인의 assets.json
```

GUI와 CLI는 같은 계획·적용 함수를 사용한다. project.refresh·project.repair-plan·project.repair를 제공한다.

기존 목록의 읽기 실패는 빈 목록과 구분하여 오류로 반환하며 ID를 재발급하지 않는다. 실제 파일 부재일 때만 초기 목록을 만든다. 플러그인의 공개 스크립트는 assets.json의 scriptName에 연결된 ID를 선언 경로보다 먼저 해석한다. 공개 파일을 이동한 뒤 옛 경로에 새 파일이 생겨도 별칭을 새 파일로 옮기지 않는다.

끊어진 등록도 생성·복사·임포트·이동 대상의 충돌 검사에 포함한다. 명시적인 복구·등록 삭제 없이 다른 ID로 교체하지 않는다. Windows의 등록 경로 비교는 대소문자를 구분하지 않으며 폴더 이동에서도 자손 ID를 함께 보존한다. 플러그인 활성화 검증도 공개 별칭의 유효 이동 경로를 사용한다.

## 결과

- 긍정: 소스 폴더 정리, 프로젝트·플러그인 일관성, 기존 ID 유지와 검토 가능한 복구.
- 부정: 외부 이동은 목록 갱신이 필요하며 중앙 JSON의 Git 충돌 가능성이 늘어난다. 확정할 수 없는 후보는 수동 선택해야 한다.
- 중립: Prefab/Level 포맷·내부 플러그인 경로·권한은 유지한다. OS의 다중 파일 트랜잭션은 보장하지 않으며 중단된 이동은 복구 창으로 해결할 수 있다.
