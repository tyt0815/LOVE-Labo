# 0041. Inspector 대상 추가는 드래그 예외보다 스포이드를 우선한다

- 상태: 채택·구현 — Prefab 계층의 자식 추가와 취소·검증을 구현했다. 데이터 계약은 [ADR 0042](0042-hierarchy-prefab-definitions.md)를 따른다.
- 날짜: 2026-10-09
- 확장: [ADR 0039](0039-lobject-templates-and-resource-picking.md)의 리소스 스포이드·일반 선택 구분
- 유지: 일반 에셋 선택의 Inspector 전환, 에셋 이동·레벨 배치 드래그

## 배경과 제약

Inspector는 일반 선택에 따라 편집 대상을 바꾼다. Inspector 내부 필드나 Prefab 오브젝트 계층으로 다른 에셋·인스턴스를 드래그하려면, 드래그 시작 시 원래 편집 대상이 사라지는 충돌이 생긴다. 리소스 지정에서 이미 같은 문제가 발생했고, Prefab 계층 자식 추가에서도 반복됐다. 사용자는 화면 공간을 늘리는 별도 편집 패널 대신 명시적인 선택 모드를 선호하며, 이후 같은 드래그 요청이 나오더라도 먼저 스포이드 대안을 제안하도록 요청했다.

## 대안과 판단 기준

- 드래그 중 Inspector를 고정하거나 이전 편집 대상을 복원하면 일반 클릭과 드래그의 선택 의미가 달라지고, 에셋 이동·배치와 예외 상태가 얽힌다.
- Inspector 고정 버튼은 사용자가 추가 상태를 관리해야 한다. Prefab 전용 편집 탭은 유효한 대안이지만 편집 화면과 탭 간 전달 동작을 추가해야 한다.
- 스포이드는 대상 지정 의도를 명시하고, 지정 모드에서만 클릭을 소비한다. 기존 리소스·인스턴스 참조 선택과 같은 상호작용을 재사용할 수 있다.

## 결정 및 근거

1. Inspector에서 리소스·인스턴스를 지정하거나 Prefab 계층에 자식을 추가할 때 스포이드 방식의 선택 모드를 우선한다. 일반 드래그에 Inspector 유지·복원 예외를 추가하지 않는다.
2. Prefab 오브젝트 계층의 우클릭 `Add Child → Pick Source`에서 추가할 부모를 먼저 확정한다. 선택 모드에서는 Inspector 전환 대신 지정된 작업이 클릭을 처리한다.
3. LObject Lua 클래스는 기본값으로 자식을 생성한다. Prefab은 원본 연결을 유지하는 중첩 Prefab으로 추가한다. 레벨 인스턴스는 현재 값과 자손을 복사하며 레벨 원본을 이동하거나 삭제하지 않는다.
4. 선택 모드는 커서로 표시한다. 성공 시 종료하고 새 자식을 선택한다. Esc·우클릭은 변경 없이 취소한다. 잘못된 대상은 오류를 보여주고 모드를 유지한다. 일반 클릭·에셋 이동·레벨 배치 드래그는 기존 동작을 유지한다.
5. 이후 Inspector 드래그앤드롭 요청이 나오면 선택과 편집 대상의 충돌을 먼저 짚고 스포이드 대안을 제안한다. 사용자가 차이를 이해한 뒤 다른 방식을 명시적으로 선택하면 새 결정으로 재검토한다. 이 정책은 사용자 요청을 영구 금지하는 규칙이 아니다.

## 예상 결과

- 긍정: Inspector 편집 대상이 안정적으로 유지되고 대상 지정과 일반 선택의 의미가 일관된다. 같은 드래그 예외 문제가 재발하는 것을 줄인다.
- 부정: 자식 추가에는 메뉴 선택과 대상 클릭이 필요하여 직접 드래그보다 단계가 늘어난다.
- 중립: 이 결정은 상호작용 정책이며 Prefab 저장 형식·상속·내부 참조·런타임 계층 생성 계약 자체를 확정하지 않는다. 중단한 구현을 자동으로 재개하거나 완료 처리하지 않는다.
