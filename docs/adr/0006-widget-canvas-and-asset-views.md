# 0006. 에디터 위젯 트리·Canvas와 에셋 보기 전환

- 상태: 채택
- 날짜: 2026-10-08
- 확장: [ADR 0002](0002-project-launcher-and-assets.md)의 에디터 UI 배치·입력과 에셋 보기

## 배경과 제약

사용자가 목록·썸네일 보기를 선택하는 드롭다운과 Widget·Slot·Canvas 구조를 함께 요청했다. 이후 플러그인의 커스텀 에디터가 구성 가능한 UI를 지향하지만, 실제 플러그인 등록 계약을 미리 고정하지 않는다. 기존 문서 저장, LObject 선택, 중앙 월드 원점과 Edit/Runtime 분리를 보존한다.

## 대안과 판단 기준

- 패널별 그리기·입력 분기를 EditorApp에 계속 추가하면 겹친 UI의 우선순위와 드래그 처리가 중복된다.
- 모든 UI를 LObject로 만들면 프로젝트·Runtime World의 생명주기와 에디터 도구가 결합된다.
- 얕은 Widget→Panel→Canvas 상속과 자식 슬롯 구성을 사용하면 기본 동작을 공유하면서 각 콘텐츠는 별도 책임을 유지한다. 기존 패널 콘텐츠는 어댑터 위젯으로 연결해 동작 전체를 다시 작성하지 않는다.
- 모든 패널의 크기 조절을 Canvas 자체에 넣으면 범용 자유 배치와 에디터의 공간 배분 규칙이 섞인다. 별도 EditorLayout이 루트 슬롯을 배치한다.

## 결정 및 근거

1. 위젯 기반 UI는 `editor/ui/`에 둔다. Widget은 영역·표시·입력 핸들러를, Panel은 자식 슬롯·그리기 순서·클리핑을, Canvas는 부모 기준 슬롯 배치를 담당한다. 현재 슬롯은 명시적 사각 영역 또는 부모 영역 채우기를 지원한다. 위젯 영역과 이벤트 좌표는 화면 기준이며 슬롯 좌표는 부모 기준이다.
2. UIRoot가 에디터 전체 그리기와 입력의 진입점이다. 클릭은 앞쪽 자식부터 판정하고, 선택된 위젯이 처리하지 않은 이벤트는 부모로 전달한다. 처리 여부와 포인터 캡처를 별도로 반환한다. 키·문자는 포커스로, 드래그 이동·해제는 캡처한 위젯으로 전달한다.
3. 드롭다운 메뉴는 루트 팝업으로 마지막에 그려 부모 클리핑 밖에서도 표시한다. 메뉴 바깥 클릭은 닫기에만 소비하며 뒤쪽 레벨 객체를 조작하지 않는다. Escape, 방향키, Enter를 지원한다.
4. EditorLayout은 계층 폭·인스펙터 폭·에셋 높이와 공유 경계 드래그를 관리한다. 최소 크기와 중앙 영역을 보장한다. 모서리에서는 두 방향을 동시에 조절한다. 크기 조절은 기존 포커스를 바꾸지 않는다.
5. 계층·뷰포트·인스펙터는 각각 Canvas 안의 콘텐츠 위젯으로 연결한다. 에셋 브라우저는 Canvas를 상속하고 폴더 트리·파일 보기·드롭다운을 자식 슬롯으로 갖는다. LObject 선택·문서 변경의 책임은 EditorApp에 유지한다.
6. 에셋은 기본 썸네일 보기와 기존 목록 보기를 지원한다. 보기 전환은 에셋 선택과 현재 폴더를 유지하고 스크롤을 초기화한다. 격자는 영역 폭에 따라 열 수를 계산하며 그리기와 클릭이 같은 계산을 사용한다.
7. 이미지 미리보기는 호스트 파일 바이트에서 88×88 텍스처로 생성한다. 현재 보이는 항목만 프레임당 최대 2개 생성하고 캐시는 최대 96개로 제한한다. 폴더 이동·Refresh에서 해제한다. 미지원·손상·대용량 이미지는 파일 아이콘으로 대체한다. 프로젝트의 Assets 경로와 각 링크 segment를 검증한 뒤 읽는다.

## 예상 결과

- 긍정: 에디터가 하나의 위젯 트리로 그리기·입력을 전달하고, 드롭다운과 중첩 콘텐츠를 재사용할 수 있다. 실제 이미지 미리보기와 패널 크기 조절이 가능하다.
- 부정: 위젯·슬롯·포커스 수명 관리가 필요하다. 썸네일 생성에는 디코딩과 GPU 작업이 추가된다.
- 중립: Core에는 UI 의존성을 추가하지 않는다. 게임용 UI 공개 API, 자동 레벨 연결, 확장자별 커스텀 에디터 등록, 도킹·자유 창 배치는 이번 결정의 구현 범위가 아니다.
