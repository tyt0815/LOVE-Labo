# 0060. 미리보기는 생명주기를 격리하고 썸네일은 저장값을 사용한다

- 상태: 승인·구현
- 2026-10-12 보완: 저장 버튼을 누르지 않은 기존 Prefab도 브라우저에서 썸네일을 표시하도록 지연 생성을 추가한다.

## 배경과 제약

Inspector 편집 값을 즉시 시각적으로 확인하면서 에셋 브라우저에서는 매 프레임 Prefab을 렌더링하지 않아야 한다. 게임 로직이 미리보기를 통해 실행되거나 authoring 값이 바뀌어서는 안 된다.

## 대안과 판단 기준

Play World를 재사용하거나 미리보기에서 초기화 콜백을 실행하는 대안은 입력·레벨 전환·오브젝트 생성 등의 부작용을 만든다. 별도 준비 World를 사용하고 draw만 호출한다. 썸네일은 초안보다 저장된 상태를 기준으로 한다.

## 결정과 근거

Preview는 WorldLoader.prepare와 공용 렌더러를 사용하며 load/update는 호출하지 않는다. 프로퍼티와 선택 변경은 별도 준비 오브젝트를 갱신한다. 미리보기 영역은 Inspector 스크롤에서 분리하고 경계 드래그로 크기를 조절한다.

Prefab의 previewBackground는 RGB 0–255의 에디터 표시 설정이며 기본 흰색이다. 일반 이미지·인스턴스의 배경은 세션 표시 설정이다. Prefab 저장 후 PNG와 원본·부모 Prefab·스크립트·이미지의 해시 영수증을 .labo/Thumbnails에 기록한다. 저장하지 않은 다른 문서 초안은 썸네일에 섞지 않는다. 브라우저에서 캐시를 조회할 때 없거나 의존성이 바뀌었으면 현재 디스크 값으로 지연 생성한다. 매 프레임 최대 두 셀을 처리하는 기존 예산을 공유한다. 실패한 셀은 Refresh 또는 캐시 무효화 전까지 재시도하지 않는다. 지연 생성은 전체 브라우저 캐시를 초기화하지 않는다.

GUI와 asset.preview CLI는 같은 Preview 모델을 사용한다. 에디터 캐시를 게임 Export에 포함하지 않는다.

asset.thumbnail CLI는 브라우저와 같은 PreviewCache.ensure를 사용해 유효 캐시를 재사용하거나 생성하며 생성 여부와 PNG·영수증 경로를 반환한다. 초안 저장이나 에셋 수정은 수행하지 않는다.

Preview는 이미지·Canvas 준비 전에 그래픽 창의 존재를 확인한다. CLI에서 창이 없으면 최소 크기 창을 생성하고 최소화하여 컨텍스트를 준비하며, 기존 에디터 창은 변경하지 않는다. 캐시 재사용은 Preview를 만들지 않으므로 창을 생성하지 않는다. 실제 CLI 프로세스 검증은 scripts/verifyThumbnailCli.ps1에서 새 캐시·오래된 캐시·재사용과 Prefab·이미지 PNG 출력을 확인한다.

## 결과

- 긍정: 즉시 편집 확인, 게임 생명주기 격리, 브라우저 렌더 비용 제한, 오래된 썸네일 검출.
- 부정: load 상태에 의존하는 draw는 미리보기에 대응해야 한다. 처음 조회하는 셀은 준비·렌더링 비용이 발생하며 생성 실패는 기본 아이콘으로 표시한다.
- 중립: 미리보기 UI와 RGB 정보는 게임 Transform·프로퍼티 계약을 변경하지 않는다.
