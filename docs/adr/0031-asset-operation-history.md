# 0031. 에셋 파일 작업과 문서 기록의 Undo/Redo

- 상태: 채택
- 날짜: 2026-10-09
- 부분 대체: [ADR 0030](0030-file-run-menu-and-document-history.md)의 파일 작업 제외 결정
- 유지: [ADR 0028](0028-agent-cli-and-standalone-game-export.md)의 Project/CLI 계약

## 배경과 제약

사용자는 클래스·Prefab·레벨 파일 및 에셋의 생성·삭제·이동·이름 변경도 기존 단축키로 되돌리기를 요청했다. 문서 스냅샷만으로는 디스크 내용과 `.meta`의 ID를 복원할 수 없다. 기존 루트·기본/열린 레벨·링크 보호를 유지하고 외부 변경을 덮어쓰지 않아야 한다. 저장 및 외부 코드 편집은 이번 범위에 포함하지 않는다.

## 대안과 판단 기준

- 파일 전체를 메모리 기록에 복사하면 큰 이미지·폴더의 비용이 크다. 파일과 메타데이터를 같은 프로젝트의 캐시로 이동하여 원본을 유지한다.
- OS 휴지통은 플랫폼·복원 경로에 의존한다. 프로젝트별 `.labo-history/<ID>/`의 payload와 manifest로 원본 위치·검증 해시를 보관한다.
- Project 자체의 모든 변경을 기록하면 CLI·테스트·내부 생성까지 GUI 세션에 종속된다. AssetBrowser에 선택적인 서비스로 연결하고 Project의 기존 API를 유지한다.
- 모든 문서 기록을 전역으로 바꾸면 기존 활성 문서 Undo 동작이 달라진다. 활성 문서와 전역 에셋 기록의 시간 순서만 비교하여 병합한다.

## 결정 및 근거

1. AssetOperations는 AssetBrowser가 포함하는 GUI 파일 작업 서비스이며 EditorApp·Project·HostFilesystem에 의존한다. Project의 삭제 사전 검사만 `deletionEntries`로 분리하여 직접 삭제와 캐시 이동이 같은 규칙을 사용한다. CLI의 삭제 의미는 유지한다.
2. New 및 브라우저에서 생성한 클래스·Prefab·레벨·폴더, 삭제, 이름 변경과 드래그/메뉴 이동을 기록한다. 생성 Undo/삭제 Redo는 캐시 이동, 반대 동작은 원래 경로 복원이다. 파일과 `.meta`를 함께 이동하고 폴더는 내부 파일·빈 폴더까지 보존한다. 이동은 기존 ID 유지·경로 갱신 로직의 역방향 작업으로 복원한다. Save·Save Level As·Export는 기록하지 않는다.
3. 에셋 명령과 문서 상태에 세션 단조 증가 번호를 부여한다. Undo는 활성 문서의 마지막 변경과 마지막 에셋 명령 중 최신 것을, Redo는 가능한 두 다음 변경 중 먼저 일어난 것을 실행한다. 문서별 100개 상태와 에셋 명령 100개를 제한하며 새 작업은 모든 Redo 분기를 폐기한다. 문서를 전환하면 문서 쪽 후보는 해당 문서의 기록이다.
4. 링크·메타데이터 단독 조작·루트 삭제 등 기존 검사를 유지한다. 캐시 이동/복원 시 전체 내용 해시를 확인한다. 이동 복원은 기존 메타데이터 ID를 확인하되 파일 내용 수정은 그대로 함께 이동한다. 목적지 및 메타데이터 충돌은 덮어쓰지 않는다. 실패하면 기록 위치를 유지하고 브라우저에 오류를 표시한다.
5. 파일/메타데이터 이동 쌍에서 두 번째 이동이 실패하면 첫 이동을 복구한다. 인덱스 갱신 실패도 원래 위치로 복구한다. 생성 직후 기록용 스냅샷 검사 실패 시 방금 생성한 항목을 제거한다. 복구 실패는 오류에 함께 표시한다. OS 프로세스 종료를 포함한 디스크 트랜잭션의 원자성은 보장하지 않는다.
6. 기록은 세션 메모리이며 재시작 후 Undo를 재개하지 않는다. 캐시는 자동 삭제하지 않아 한도/Redo 폐기/종료 후에도 삭제 원본을 남긴다. 필요 없으면 에디터 종료 후 수동 삭제한다. manifest는 위치·해시 확인용이며 자동 복구 명령은 제공하지 않는다.
7. 기본/열린 레벨은 계속 삭제 금지이며 생성 취소도 같은 규칙을 따른다. 먼저 다른 레벨을 열어야 한다. 저장하지 않은 Prefab을 포함하는 경로도 삭제를 거절한다. 문서 저장 기준과 authoring ID 최고 사용값은 기존 규칙을 유지한다.

## 관계

```text
EditorApp
├─ 포함 → 문서별 History + 전역 에셋 명령 기록
└─ 포함 → AssetBrowser
           └─ 포함 → AssetOperations
                      ├─ 의존 → EditorApp (기록·Inspector 갱신)
                      ├─ 의존 → Project (검사·ID 인덱스)
                      └─ 의존 → HostFilesystem (.labo-history 원본 보관)
```

## 예상 결과

- 긍정: 생성·삭제·이동 실수를 문서 편집과 함께 되돌리고 원본 바이트와 리소스 ID를 보존한다. CLI/파일 형식 계약을 유지한다.
- 부정: 폴더 전체 검사 비용과 캐시 디스크 사용량이 발생한다. 자동 정리가 없으므로 필요에 따라 수동 관리해야 한다. 외부 변경·열린 문서 보호 때문에 일부 Undo는 거절될 수 있다.
- 중립: 저장 및 외부 Lua 편집의 되돌리기, 재시작 후 기록 복구, CLI Undo는 제공하지 않는다.
