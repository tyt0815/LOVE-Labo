# 0095. PIE 런타임 편집과 입력 소유권

- 상태: 채택·구현
- 부분 대체: [0067](0067-fixed-play-pause-stop-controls.md)의 Pause 표시·조작과 스냅 비활성 정책
- 유지: [0085](0085-public-projection-layout-and-input.md)의 공개 API 기반 구성, 편집 문서와 Runtime World 분리

## 배경과 제약

생성된 인스턴스와 현재 프로퍼티를 확인하고, 실행을 멈추지 않고 시점을 옮기거나 Pause에서 값을 수정해야 한다. Stop 후에는 기존 미저장 편집과 선택·시점을 보존한다. 프로젝트 Lua의 LÖVE 입력 조회와 마우스 숨김도 에디터 조작을 방해하지 않아야 한다.

## 대안과 판단 기준

- 편집 문서에 런타임 값을 복사하면 원본·Undo·Prefab 미리보기와 섞인다.
- 별도 Inspector를 작성하면 같은 스키마·입력 위젯이 중복된다.
- 이벤트만 차단하면 직접 isDown 조회와 눌린 상태를 기억하는 게임 코드가 에디터 입력을 계속 사용한다.

## 결정 및 근거

게임 조작·자유 탐색·일시정지 세 상태를 제공한다. Pause는 자유 탐색으로 전환하며 Resume는 자유 탐색을 유지한다. Step은 1/60초의 Update 한 번과 레벨 전환 경계를 실행한다. draw에서 변경하는 사용자 상태나 독립적으로 재생하는 오디오까지 동결하는 기능은 아니다.

RuntimeScene은 실제 객체를 감싼 UI 전용 객체를 유지한다. UI 식별자는 runtimeId이며 원본 authoringId를 바꾸지 않는다. Transform·Script 값은 실제 인스턴스에 적용한다. 참조는 UI 식별자와 실제 객체·Script 사이에서 변환한다. 기존 Inspector·SceneView·Hierarchy를 재사용하며 문서 저장·Undo·Prefab 확장은 편집 상태에서만 실행한다. 런타임 부착 구성·복제·재부모화는 제공하지 않는다. 생성·삭제는 기존 spawnLObject·removeLObject를 사용한다.

자유 탐색 진입은 현재 출력의 중심·배율을 참고하되 월드 축 기준 Scene View로 전환한다. 게임 투영·카메라는 변경하지 않는다. 레벨 전환은 새 RuntimeScene에 연결하며 오래된 선택을 지운다. Stop·오류는 런타임을 폐기하고 기존 편집 선택·시점을 복원한다.

PlayInput은 프로젝트 및 플러그인 Lua의 love/require("love.*")에 세션별 입력 환경을 제공한다. 키보드·마우스·조이스틱 상태 조회를 중재하고 커서 표시·상대 모드·가두기·커서 모양 요청을 기억한다. 에디터는 자유 탐색·Pause·UI 포커스·팝업·포커스 상실 때 게임 입력을 해제한다. 이미 전달한 누름에는 합성 해제 이벤트를 보내며 포인터 캡처를 취소한다. 게임 복귀 때 마지막 마우스 요청을 적용하고 종료 때 호스트 상태를 복원한다. 게임 Lua의 사용자 정의 네이티브 호출까지 격리하는 보안 샌드박스는 아니다.

```text
EditorApp ──포함──> RuntimeScene·PlayInput
Hierarchy·SceneView·Inspector ──의존──> RuntimeScene ──참조──> Runtime World·LObject·Script
프로젝트·플러그인 Lua 환경 ──의존──> PlayInput ──의존──> 호스트 LÖVE 입력
Core ──에디터 의존 없음
```

입력 소유권 해제는 Pointer 영역의 일반 `onUp`으로 전달하지 않고 캡처만 취소한다. 이미 전달한 LÖVE 마우스·터치 누름의 해제 이벤트에는 현재 좌표를 사용한다. 마우스는 호스트 위치를, 터치는 활성 터치 위치 또는 마지막 이동 위치를 사용하므로 누름 위치로 돌아가 클릭을 발생시키지 않는다.

## 예상 결과

- 긍정: 실행 결과를 직접 조작하면서 원본 문서와 미저장 편집을 보존한다.
- 부정: Lua 입력 프록시와 실제 입력의 차이를 관리해야 한다. 회전·비균일 배율의 게임 투영을 자유 탐색 화면이 그대로 복제하지는 않는다.
- 중립: 에셋 형식·게임 공개 API·Export의 LÖVE 입력은 유지한다. 사용자 파일 쓰기는 Stop으로 되돌리지 않는다.
