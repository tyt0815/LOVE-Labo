# 0030. 파일·실행 메뉴와 문서 Undo/Redo

- 상태: 채택
- 파일 작업 제외 결정은 [ADR 0031](0031-asset-operation-history.md)로 대체한다.
- 날짜: 2026-10-09
- 확장: [ADR 0006](0006-widget-canvas-and-asset-views.md)의 위젯 트리, [ADR 0024](0024-collapsible-details-and-property-columns.md)의 Inspector 배치
- 유지: [ADR 0028](0028-agent-cli-and-standalone-game-export.md)의 공용 생성·저장·Export 로직

## 배경과 제약

사용자는 상단에 파일·실행 메뉴만 두고 Undo/Redo는 Ctrl+Z·Ctrl+Shift+Z로 사용하기를 요청했다. 버튼은 기존 Refresh처럼 기본 배경·테두리를 표시하지 않으며 배경 위에 놓고 별도 패널 박스를 만들지 않는다. 메뉴가 기존 작업 패널·입력·기즈모를 가리지 않아야 한다.

## 대안과 판단 기준

- 패널 위에 메뉴를 겹치면 제목·클릭 영역이 충돌한다. 상단 32px을 확보하고 작업 패널·Inspector 좌표와 실제 클리핑을 함께 내린다.
- 별도의 메뉴 팝업 구현은 방향키·Escape·하위 메뉴 처리가 중복된다. MenuBar가 기존 ContextMenu를 포함하고 단축키 표시·메뉴 전환을 확장한다.
- 모든 mutation에 명령 객체를 추가하면 기존 입력·override·드래그 코드를 크게 바꿔야 한다. 현재 크기의 문서는 직렬화 스냅샷으로 기록하고 입력 완료 시점을 경계로 묶는다.
- 매 프레임 기록은 드래그·숫자 변경을 여러 단계로 나눈다. 입력 확정·마우스 해제 등에서만 기록하고 활성 편집·드래그 중에는 보류한다.

## 결정 및 근거

1. MenuBar는 Widget를 상속하며 EditorApp이 포함한다. File 메뉴는 New의 옆 서브메뉴에 Class·Prefab·Level 생성을 묶고 Save·Save Level As·Export Game을 제공한다. Run 메뉴는 Play·Stop 상태에 따라 활성 항목을 바꾼다. 사용자 요청에 따라 메뉴 이름·항목은 영어로 통일하며 기존 단축키도 유지한다.
2. 평소 메뉴 버튼은 배경·테두리 없이 그린다. 호버·열림 상태만 공통 테마 색으로 강조하고 별도 상단 패널 배경을 추가하지 않는다. 메뉴가 열려 있을 때 다른 탭으로 마우스를 이동하면 팝업을 전환한다.
3. Ctrl+Z는 Undo, Ctrl+Shift+Z는 Redo이며 메뉴에 항목을 추가하지 않는다. 레벨 배치·복제·삭제·Transform·선언/컴포넌트 프로퍼티와 Prefab override 편집을 기록한다. 편집 중 단축키를 누르면 현재 값을 확정한 뒤 한 단계 되돌린다. 캡처 해제 전에 스냅 숫자 드래그도 종료해 커서·상대 마우스 상태를 복원하며, 이 정리는 취소/복원할 문서 기록이 없어도 수행한다. 스냅 값은 확정하지만 문서 Undo 대상에는 넣지 않는다. 팝업은 기존처럼 키 입력을 우선 소비하고 Play 중에는 문서 Undo를 실행하지 않는다.
   캡처 해제는 `Root:cancelCapture()`로 공유한다. 이미 확정한 편집 외에도 실제 캡처 소유자에게 취소를 전달하여 내부 상태를 정리한다. 패널 리사이즈의 취소는 drag·리사이즈 표시를 지우고 기본 커서를 복원하며, 취소 시점의 패널 크기는 유지한다.
4. History는 EditorApp이 문서별로 포함하는 최대 100개 상태의 메모리 스냅샷이다. 레벨과 Prefab 기록은 분리한다. 드래그·필드 편집 한 번을 한 단계로 기록하며 선택·카메라·패널·스냅 설정은 편집 기록에 넣지 않는다. Inspector와 ClassInspector는 필드 확정 직후 EditorApp에 알리므로 Enter 없이 다음 필드를 클릭해도 이전 변경을 먼저 기록한다. Undo 뒤 새 편집은 Redo 분기를 제거한다.
5. Undo는 메모리의 문서 데이터만 복원하고 저장 기준 스냅샷은 유지한다. 따라서 저장 시점으로 돌아오면 clean이고 다른 상태는 dirty이다. 선택은 authoring ID로 복원하며 ID의 최고 사용값을 유지해 새 분기에서 삭제·취소된 ID를 재사용하지 않는다.
6. 파일 시스템의 에셋 생성·삭제·이동, 프로젝트 Lua 소스 수정은 Undo 범위에 포함하지 않는다. 새 문서를 열면 그 문서의 기록에서 시작한다. 디스크를 되돌리거나 Runtime 상태를 authoring 데이터에 쓰지 않는다.

## 관계

```text
EditorApp
├─ 포함 → MenuBar ─ 상속 → Widget
│          └─ 포함 → ContextMenu
└─ 포함 → 문서별 History
            └─ 의존 → 기존 Level/Prefab 직렬화
```

## 예상 결과

- 긍정: 기본 명령의 위치가 명확해지고 실수한 문서 편집을 되돌릴 수 있다. 기존 저장·직렬화·Play 경계를 유지한다.
- 부정: 상단 공간과 Inspector 좌표가 바뀌어 좌표 기반 테스트가 달라진다. 큰 레벨은 스냅샷 직렬화·메모리 비용이 있으며 기록 수를 제한한다.
- 중립: Core·CLI·파일 형식·디스크 생성 API는 변경하지 않는다. 텍스트 커서 이동 단위의 Undo나 디스크 트랜잭션 Undo는 제공하지 않는다.
