# 0026. 리소스 프로퍼티 미리보기와 에셋 위치 찾기

- 상태: 채택
- 날짜: 2026-10-09
- 확장: [ADR 0024](0024-collapsible-details-and-property-columns.md)의 Details 행 배치
- 관련: [ADR 0011](0011-asset-ids-metadata-and-path-cache.md)의 안정적인 에셋 ID

## 배경과 제약

이미지 프로퍼티와 선택 목록에서 정사각형 미리보기를 제공하고, 리소스 선택은 경로 대신 파일 이름을 표시한다. 선택한 리소스를 에셋 브라우저에서 찾을 수 있어야 한다. 찾기 때문에 편집 중인 인스턴스·Prefab 대상이 바뀌어서는 안 된다. 그룹 헤더 높이는 접힘·펼침에 관계없이 동일해야 한다.

## 대안과 판단 기준

- 원본 이미지를 Inspector마다 로드하면 메모리와 프레임 비용이 커진다. 기존 AssetThumbnail의 제한된 캐시·프레임당 생성 예산을 재사용한다.
- 브라우저의 일반 선택 콜백을 호출하면 Inspector 대상이 전환된다. 위치 찾기는 폴더 이동·목록 선택·스크롤만 수행한다.
- 이미지 목록만 별도 팝업으로 구현하면 키보드 선택과 스크롤 동작이 중복된다. 기존 Dropdown에 행 높이와 옵션 그리기 콜백을 제공한다.

## 결정 및 근거

1. 공통 그룹 헤더는 32px이다. 기본 프로퍼티 행은 32px, 이미지 행과 이미지 선택 항목은 96px이다. 가변 행 높이로 그룹 크기·스크롤·클릭 영역을 계산한다.
2. 이미지 프로퍼티의 오른쪽 열에는 정사각형 미리보기, 파일 이름 선택기, 그 아래 찾기·초기값 복원 아이콘을 배치한다. 좁은 Inspector에서는 미리보기도 열 너비에 맞춰 줄인다.
3. 리소스 이름 표시는 경로의 마지막 파일 이름만 사용하며 실제 값은 기존 에셋 ID 또는 참조를 유지한다. Parent Class와 생성 대화상자도 동일한 표시 정책을 적용한다.
4. ClassInspector는 AssetThumbnail 캐시를 소유하고 UI의 미리보기 그리기와 Dropdown의 가변 행 렌더링에 의존한다. EditorApp은 찾기 요청을 AssetBrowser의 reveal로 연결한다. 이 관계는 상속이 아닌 포함·의존이다.
5. reveal은 현재 에셋 ID를 경로로 해석하여 폴더를 열고 파일을 선택한 후 목록·폴더 트리의 스크롤을 맞춘다. EditorApp은 접힌 브라우저를 먼저 펼친다. 일반 선택 콜백과 Inspector 선택 출처는 변경하지 않는다.

## 예상 결과

- 긍정: 이미지 식별과 리소스 탐색이 쉬워지고 접기 시 헤더 크기가 안정적이다.
- 부정: 이미지 행은 더 많은 공간을 사용하며 같은 이름의 파일은 목록에서 이름만으로 구분하기 어렵다.
- 중립: Core·직렬화·참조 해석·override 저장 계약은 변경하지 않는다. 미리보기 캐시는 기존 크기 및 생성 예산 제한을 유지한다.
