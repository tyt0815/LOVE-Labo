# 0008. 공통 컨텍스트 메뉴와 프로젝트 항목 생성·삭제

- 상태: 채택
- 날짜: 2026-10-08
- 확장: [ADR 0006](0006-widget-canvas-and-asset-views.md)의 팝업 입력과 [ADR 0007](0007-sources-and-level-scripts.md)의 프로젝트 탐색·레벨 연결

## 배경과 제약

에셋 브라우저의 우클릭 메뉴에 New와 항목 위에서만 보이는 Delete가 필요하다. New는 Folder·Level·Lua Script 하위 메뉴를 제공한다. 다른 패널에서도 컨텍스트 메뉴를 사용할 수 있어야 하지만 실제 동작과 프로젝트 파일 책임은 UI 공통 모듈에 넣지 않는다. 기존 프로젝트 상대 경로, 링크 탐색 금지, 레벨 JSON과 Lua의 명시적 연결을 유지한다.

## 대안과 판단 기준

- 브라우저에서 메뉴를 직접 그리면 다른 패널의 팝업 배치·입력 처리가 중복된다. 데이터 기반 ContextMenu 위젯과 공통 Dialog 위젯을 사용한다.
- 새 레벨을 JSON만 생성하면 실행 코드 연결이 비어 있다. Assets 하위 경로에 대응하는 Sources 경로에 같은 이름의 Lua를 생성하여 기존 기본 레벨과 동일한 연결을 제공한다.
- 삭제를 즉시 실행하면 폴더 내용까지 실수로 지울 수 있다. 명시적인 확인 창을 제공한다. 휴지통 통합이나 Undo 계약은 이번에 추가하지 않는다.

## 결정 및 근거

1. `editor/ui/context_menu.lua`는 label·enabled·action·children 항목으로 메뉴를 구성한다. 화면 경계에 맞춰 메뉴를 배치하고 호버·클릭·방향키·Enter·Escape를 처리한다. UIRoot의 팝업으로 그려 다른 패널의 클리핑 영향을 받지 않는다. 팝업이 열려 있는 동안 배경 입력을 소비하되, 컨텍스트 메뉴의 새 우클릭은 기존 메뉴를 닫고 해당 위치의 위젯에 전달하여 메뉴를 바로 다시 열 수 있게 한다. 이 예외는 입력·삭제 확인 창이나 드롭다운에는 적용하지 않는다.
2. `editor/ui/dialog.lua`는 이름 입력과 삭제 확인에 사용한다. 텍스트 입력도 UIRoot에서 팝업으로 전달하며 실패 시 창을 유지하고 오류를 표시한다.
3. 브라우저의 빈 공간 메뉴는 New만 제공한다. 파일·폴더 메뉴에는 Delete를 추가한다. Assets·Sources 루트에는 Delete를 표시하지 않는다. 트리에서는 우클릭한 폴더, 파일 영역에서는 현재 폴더에 생성한다. New에는 현재 폴더에서 생성 가능한 항목만 표시한다. Assets에서는 Folder·Level, Sources에서는 Folder·Lua Script를 보여준다.
4. `Project:createEntry`는 이름을 검증하고 기존 파일을 덮어쓰지 않는다. Level은 대응하는 Sources 하위 경로에 Lua 템플릿을 생성하고 `scriptReference`로 연결한다. 중간 실패 시 이번에 생성한 파일·빈 폴더만 정리한다. 같은 이름의 Lua가 있으면 재사용하거나 교체하지 않고 실패한다.
5. `Project:deleteEntry`는 루트와 프로젝트 기본 레벨을 포함하는 경로를 거부한다. EditorApp은 현재 열린 레벨을 포함하는 경로도 거부한다. 일반 폴더는 하위 내용까지 삭제하며 삭제 확인에는 영구 삭제임을 표시한다. 레벨을 삭제해도 연결된 Lua를 자동 삭제하지 않으며 다른 레벨의 참조도 자동 수정하지 않는다.
6. 삭제 전에 전체 하위 경로의 경계·링크 여부를 검사하고 각 삭제 직전에도 다시 검사한다. 링크가 포함된 폴더는 삭제하지 않는다. 파일 잠금이나 외부 변경으로 도중 실패하면 이미 삭제한 항목을 복구하지 못하므로 브라우저를 새로 읽고 오류를 표시한다. 외부 프로세스와의 완전한 원자성은 제공하지 않는다.

## 예상 결과

- 긍정: 다른 패널에서 같은 메뉴·입력 창을 재사용할 수 있고 브라우저에서 실제 항목 생성·삭제가 가능하다. 새 레벨은 실행 코드와 명시적으로 연결된다.
- 부정: 영구 삭제는 Undo가 없으며 외부 파일 변경·잠금에 의한 부분 실패 가능성이 있다. 참조된 Lua를 직접 삭제하면 해당 레벨의 다음 Play는 실패할 수 있다.
- 중립: Core에는 UI나 파일시스템 의존성을 추가하지 않는다. 기본 레벨 지정 변경, 파일 이름 변경·이동, 참조 자동 수정, 플러그인 메뉴 등록은 이번 범위에 포함하지 않는다.
