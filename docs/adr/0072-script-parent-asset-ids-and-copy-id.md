# 0072. 스크립트 부모 참조를 에셋 ID로 작성하고 브라우저에서 복사한다

- 상태: 승인·구현
- 관련: [0012](0012-lua-classes-properties-and-unsaved-levels.md), [0058](0058-plugins-and-mounted-assets.md), [0066](0066-central-asset-catalog-and-reference-repair.md)

## 배경과 제약

사용자 스크립트는 부모 UUID를 기록하지만 플러그인 부모는 공개 이름을 기록하여 같은 extends의 의미가 달랐다. 사용자는 부모 참조를 ID로 통일하고 브라우저에서 원본 ID를 얻기를 요청했다. 에셋 이동·이름 변경·Export 및 기존 프로젝트 호환성을 유지한다.

## 대안과 판단 기준

전역 스크립트 이름 중복 금지는 읽기 편하지만 파일 이동·이름 변경 시 참조 유지 문제를 해결하지 못하고 플러그인과 프로젝트의 이름 영역을 제한한다. 경로 참조도 이동에 취약하다. UUID는 이미 중앙 목록에서 관리하므로 추가 식별 체계를 만들 필요가 없다.

## 결정 및 근거

새 Script·Level 상속 코드는 사용자·플러그인 모두 부모 에셋 UUID를 기록한다. 기반 Script는 에셋이 아니므로 extends를 생략한다. 기존 공개 이름·Script 별칭은 읽기 호환으로 해석하며 로딩한 정의의 부모 필드를 ID 또는 기본 부모 생략으로 정규화한다. 기존 사용자 파일을 임의로 다시 쓰지 않는다. require("Engine")의 공개 클래스 이름은 에셋 상속 참조와 다른 API이며 유지한다.

에셋 브라우저 우클릭의 Copy ID는 프로젝트·읽기 전용 플러그인의 등록 파일 ID를 복사한다. 폴더·링크·미등록 항목에는 제공하지 않는다. Inspector의 Copy ID는 부착 ID이므로 두 의미를 가이드에서 구분한다. 서로 다른 폴더의 동명 스크립트를 금지하지 않는다. 같은 폴더의 파일명 충돌과 기존 플러그인 공개 API 별칭 중복 검사는 유지한다.

## 예상 결과

- 긍정: 부모 파일 이동·이름 변경에 안정적인 하나의 참조 형식과 ID 획득 동선을 제공한다.
- 부정: Lua 소스의 UUID만으로 부모 이름을 읽기는 어렵다.
- 중립: Script·Level 종류와 플러그인 공개 API 및 기존 별칭의 읽기 호환은 유지한다.
